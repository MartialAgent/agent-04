# 2-2단계 — 도달점: 에이전트 껍데기(Agent Shell) 만들기

🟡 **전원 권장** — 2-1단계에서 만든 채팅창 뒤에 **판단하고 도구를 쓰는 에이전트**를 넣습니다.
**설치도, API 키도, 계정도, 인터넷도 필요 없습니다.** `index.html` 더블클릭이면 끝입니다.

---

## 1. 이 단계의 목적

2-1단계 마지막에 이 아쉬움이 남았습니다.

> "`data.js`의 표에 없는 말을 못 알아듣는다."

표를 100줄로 늘려도 101번째 질문에서 똑같이 막힙니다. 필요한 건 **판단하는 것**입니다.
그런데 판단만으로도 부족합니다. 모델은 **우리 회사 재고도, 우리 부서 규정도 모릅니다.**

| | 챗봇 | **에이전트** |
|---|---|---|
| 동작 | 질문 → 답 (1회성) | **판단 → 행동 → 확인 → 다시 판단** (반복) |
| 도구 | 없음. 아는 것만 말함 | **도구를 직접 씀** |
| 모르는 걸 물으면 | 그럴듯하게 **지어냄** | 도구로 **찾아본 뒤** 답함 |
| 비유 | 안내데스크 직원 | 일을 통째로 맡기는 비서 |

**도메인 적용에서 이 차이가 결정적입니다.**
"재고 있어요?"에 챗봇은 그럴듯한 숫자를 지어냅니다. 에이전트는 재고표를 **찾아보고** 답합니다.

```
심장 (도메인마다 다름)  →  껍데기 : 화면 + 에이전트 구조 + 도구 데이터   ← 2단계
뼈대 (원우 전원 공통)   →  내용물 : 파이썬 · LLM · 진짜 모델            ← 3~5단계
```

## 2. ★ 여기서 진짜인 것 / 가짜인 것

**먼저 읽고 넘어가세요.** 나중에 헷갈립니다.

| | 진짜 | 가짜 (더미) |
|---|---|---|
| 그래프 구조 (노드·엣지·상태·조건분기·반복) | ✅ | |
| 도구를 쓰고 **근거를 남기는** 흐름 | ✅ | |
| 화면이 진행 과정·근거를 보여주는 방식 | ✅ | |
| **판단하는 두뇌** | | ❌ `brain.js`의 규칙 (if 문) |
| **조회하는 사내 데이터** | | ❌ `data.js`의 표 |
| **로그인** | | ❌ 이름만 적으면 통과 |
| **서버** | | ❌ `agent.js`의 `Backend`가 대신함 |

### 왜 두뇌를 가짜로 하나

2단계의 목표는 **껍데기를 손에 쥐는 것**입니다.
여기서 API 키를 요구하면 전원이 **키 발급·과금·네트워크 오류에서 시간을 다 씁니다.**

**진짜 LLM은 3~5단계에서 붙입니다.** 그때 바뀌는 건 **`brain.js` 파일 하나뿐**입니다.
나머지는 한 줄도 안 고칩니다. 그래서 지금 구조를 제대로 만들어두는 게 의미가 있습니다.

> 💡 규칙 기반은 **항상 똑같이 답합니다.**
> "내가 코드를 잘못 짠 건지, 모델이 딴소리를 한 건지" 헷갈릴 일이 없습니다.
> 구조를 배우기에는 오히려 유리합니다.

### 왜 서버를 안 만드나

2단계는 **2-1도 2-2도 브라우저 안에서 끝납니다.** 설치·실행에서 막히는 사람이 없도록 그렇게 정했습니다.

다만 서버가 하던 일의 **모양은 그대로 남겨둡니다.**

```js
Backend.chat(question, threadId)   →   fetch("/api/chat", ...)
```

**이 한 줄을 바꾸면 그대로 서버 버전이 됩니다.** 그 완성된 서버 코드는
[`example/app.py`](example/README.md)에 **읽을거리로** 넣어뒀습니다. 만들지는 않습니다.

## 4. 만들 것 — 한 화면

채팅으로만 더듬는 화면이 아닙니다. **기능을 직접 눌러보고 대화도 하는** 한 페이지입니다.

```
┌─────────────────────────────┬────────────────────────────────┐
│ 📦 사내 데이터 [더미]        │  💬 대화 [두뇌만 더미]          │
│   A-1023 브라켓  48  3일     │    말풍선 + 근거 칩            │
│   B-2041 힌지     0  3주     │    ▸ 에이전트가 한 일 3단계     │
│   ↑ 누르면 도구가 바로 돈다   │                                │
│ 🔧 도구 [진짜]               │                                │
│   [A-1023] [lookup] [list]  │                                │
│ 🧠 걸어간 길                 │                                │
│   시작 → 🧠think ⇄ ⚙️action → 끝 │  [입력창]         [보내기]  │
└─────────────────────────────┴────────────────────────────────┘
```

### 🎯 왼쪽과 오른쪽이 이 화면의 전부입니다

| | 🔧 도구 패널 | 💬 대화 |
|---|---|---|
| 어떤 도구를 쓸지 | **내가** 고른다 | **에이전트가** 고른다 |
| 부르는 함수 | `lookup()` | `lookup()` — **같은 함수** |
| 그래서 이건 | 그냥 프로그램 | **에이전트** |

**결과는 같습니다. 다른 건 누가 골랐느냐 뿐입니다.**

## 5. 여섯 단계 — 무엇을 더하면 무엇이 달라지는가

| STEP | 더하는 것 | 그때 느껴야 하는 것 |
|---|---|---|
| **1** | `brain.js` — 판단 | 표를 찾는 게 아니라 **"도구를 쓸까 말까"를 정한다** |
| **2** | `agent.js` — 그래프 + 도구 | 판단 → 행동 → **다시 판단**으로 돈다 |
| **3** | 화면 연결 + 진행 과정 | **챗봇과 다르다는 게 눈에 보인다** ← ★ |
| **4** | 근거 칩 | 지어낸 말인지 **찾아본 말인지** 구분된다 |
| **5** | 한 화면으로 펴기 | 도구를 **내가** 고르는 것과 **쟤가** 고르는 것의 차이 |
| **6** | 로그인 + 대화방 | 사용자가 구분되니 **방도 나뉜다** |

> 🎯 **STEP 2 → 3이 이 단계의 핵심입니다.**
>
> STEP 2가 끝나면 **에이전트는 이미 진행 과정을 만들고 있습니다.** 화면이 안 보여줄 뿐입니다.
> STEP 3에서 화면이 그걸 그립니다.
>
> **화면이 똑똑해진 게 아니라 에이전트가 더 알려준 것입니다.**
> "프론트에 기능이 생겼다"의 정체가 대부분 이것입니다.

## 6. 그래프 구조 — 3개 단어

**그래프의 아이디어는 AI의 작업 흐름을 순서도로 그리는 것**입니다.

- **노드(Node)** = 작업 한 단계 (함수 하나)
- **엣지(Edge)** = 화살표, "다음엔 이거 해"
- **상태(State)** = 노드들이 주고받는 공유 메모장

이 셋만 알면 80%입니다.

```
       ┌───────────────────────────────────┐
       │                                   │ (도구 결과를 들고 다시 판단)
 [시작]─▶[think: 판단]──조건분기──▶[action: 행동 = 도구 실행]
                          │
                          └──(도구 필요 없음)──▶[끝]
```

> ★ **에이전트를 에이전트답게 만드는 건 딱 두 개입니다.**
> ① **갈림길(조건 분기)** ② **되돌아가는 화살표(반복)**
>
> 챗봇에는 이 둘이 없습니다.

**두 갈래를 다 봐야 이해한 것입니다.**

```
💬 B-2041 언제 들어와?          💬 안녕?
  🧠 [think] 판단 중...           🧠 [think] 판단 중...
  ⚙️ [action] 도구 실행          ✅ 답변: 안녕하세요! ...
  🔧 [도구] lookup('B-2041')
  🧠 [think] 판단 중...          ← action 없이 끝. 이게 갈림길의 다른 쪽 길
✅ 답변: 재고 0개, 납기 3주
```

### LangGraph는 어디에?

이 단계에서는 이 흐름을 **라이브러리 없이 `while` 반복으로 직접 돕니다.**
같은 그래프를 LangGraph로 선언한 버전이 [`example/agent.py`](example/README.md)에 있습니다.

```
agent.py :  graph.add_conditional_edges("think", route, {...})   ← 선언한다
agent.js :  while (true) { ... if (route() === END) break; }      ← 직접 돈다
```

하는 일은 같습니다. **선언해두면 중단·재개·병렬·기록이 공짜로 따라옵니다.**
그게 LangGraph를 쓰는 이유이고, **4~5단계에서 진짜로 씁니다.**

## 8. 배포 = URL이 생기는 것 🟢

- 지금 만든 것은 **내 컴퓨터의 파일**입니다. 남에게 주려면 파일을 통째로 보내야 합니다
- 남이 **주소로** 들어와 쓰게 하려면 24시간 켜진 컴퓨터(서버)에 올려야 합니다 → 그게 배포

> **실제 배포는 하지 않습니다.** 무료 배포 서비스도 계정 가입·카드 등록에서 시간을 다 잡아먹습니다.
> **개념 설명 + Agent Room 실물 시연**으로 대체합니다.
>
> 다만 배포로 가는 길은 이미 열려 있습니다 — `Backend`를 [`example/app.py`](example/README.md)처럼
> 서버로 옮기고, `fetch`로 부르면 됩니다. **구조를 다시 짤 필요가 없습니다.**

## 9. 내 도메인에 적용하기 🟢

같은 껍데기가 모든 도메인을 받아냅니다. **바꾸는 건 세 칸뿐입니다.**

| 도메인 | 화면 입력 라벨 | 도구가 찾아올 것 (`data.js`) | 에이전트가 만들 결과 |
|---|---|---|---|
| 영업 | "고객사 정보" | 과거 제안서 · 단가표 | 제안서 초안 |
| 행정 | "민원 내용" | 부서별 업무분장표 | 담당부서 분류 + 회신문 |
| 연구 | "논문 URL" | 내 서지 목록 | 요약 + 선행연구 정리 |
| 제조 | "품번" | 재고 · 납기 테이블 | 납기 회신문 |
| 인사 | "이력서 텍스트" | 직무기술서 | 적합도 요약 |
| 마케팅 | "제품 설명" | 브랜드 톤 가이드 | 카피 3안 |
| **내 도메인** | | | |

> 🎯 **맨 아랫줄을 채우세요. 코딩보다 이게 더 중요합니다.**
> 가운데 칸이 안 떠오르면, **그게 진짜 과제입니다.**
