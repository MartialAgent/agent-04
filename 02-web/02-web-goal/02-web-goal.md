# 2-2단계 — 도달점: 에이전트 껍데기(Agent Shell) 만들기

🟡 **전원 권장** — 2-1단계에서 만든 채팅창 뒤에 **판단하고 도구를 쓰는 에이전트**를 넣습니다.
**API 키도, 계정도, 인터넷도 필요 없습니다.**

---

## 1. 이 단계의 목적

2-1단계 마지막에 이 아쉬움이 남았습니다.

> "규칙표에 없는 말을 못 알아듣는다."

규칙을 100개로 늘려도 101번째 질문에서 똑같이 막힙니다. 필요한 건 **판단하는 것**입니다.
그런데 판단만으로도 부족합니다. 모델은 **우리 회사 재고도, 우리 부서 규정도 모릅니다.**

| | 챗봇 | **에이전트** |
|---|---|---|
| 동작 | 질문 → 답 (1회성) | **판단 → 행동 → 확인 → 다시 판단** (반복) |
| 도구 | 없음. 아는 것만 말함 | **도구를 직접 씀** |
| 모르는 걸 물으면 | 그럴듯하게 **지어냄** | 도구로 **찾아본 뒤** 답함 |
| 비유 | 안내데스크 직원 | 일을 통째로 맡기는 비서 |

**도메인 적용에서 이 차이가 결정적입니다.**
"재고 있어요?"에 챗봇은 그럴듯한 숫자를 지어냅니다. 에이전트는 재고표를 **찾아보고** 답합니다.

```
심장 (도메인마다 다름)  →  껍데기 : 화면 + 서버 + 도구 데이터   ← 2단계
뼈대 (원우 전원 공통)   →  내용물 : 파이썬 · LLM · 에이전트 구조  ← 3~5단계
```

## 2. ★ 여기서 진짜인 것 / 가짜인 것

**먼저 읽고 넘어가세요.** 나중에 헷갈립니다.

| | 진짜 | 가짜 (더미) |
|---|---|---|
| 그래프 구조 (노드·엣지·상태·조건분기·반복) | ✅ 진짜 LangGraph | |
| 서버 · API 계약 · 화면 | ✅ 진짜 | |
| 도구를 쓰고 결과를 받아 답하는 흐름 | ✅ 진짜 | |
| **판단하는 두뇌** | | ❌ `brain.py`의 규칙 (if 문) |
| **조회하는 사내 데이터** | | ❌ `data.py`의 딕셔너리 |
| **로그인** | | ❌ 이름만 적으면 통과 |

### 왜 두뇌를 가짜로 하나

2단계의 목표는 **껍데기를 손에 쥐는 것**입니다.
여기서 API 키를 요구하면 전원이 **키 발급·과금·네트워크 오류에서 시간을 다 씁니다.**

**진짜 LLM은 3~5단계에서 붙입니다.** 그때 바뀌는 건 **`brain.py` 파일 하나뿐**입니다.
나머지는 한 줄도 안 고칩니다. 그래서 지금 구조를 제대로 만들어두는 게 의미가 있습니다.

> 💡 규칙 기반은 **항상 똑같이 답합니다.**
> "내가 코드를 잘못 짠 건지, 모델이 딴소리를 한 건지" 헷갈릴 일이 없습니다.
> 구조를 배우기에는 오히려 유리합니다.

## 4. 프론트 한 번, 백 한 번 — 여섯 단계

이번 단계는 **번갈아** 갑니다. 그리고 그 리듬 자체가 교재입니다.

| STEP | 어디 | 더하는 것 | 그때 느껴야 하는 것 |
|---|---|---|---|
| **1** | 🔧 백 | 규칙표 → **LangGraph 에이전트** | "화면을 한 줄도 안 고쳤는데 답이 똑똑해졌다" |
| **2** | 🖥 프론트 | 진행 과정 표시 | "**챗봇과 다르다는 게 눈에 보인다**" ← ★ |
| **3** | 🔧 백 | 도구 추가 + 근거 반환 | "도구를 더하는 건 함수 하나 더 쓰는 일이구나" |
| **4** | 🖥 프론트 | 근거 칩 | "지어낸 말인지 찾아본 말인지 구분된다" |
| **5** | 🔧 백 | 더미 로그인 + 대화방 분리 | "사용자가 구분되니 방도 나뉜다" |
| **6** | 🖥 프론트 | 로그인 화면 + 대화 이어가기 | "서비스처럼 보이기 시작한다" |

> 🎯 **STEP 1 → 2가 이 단계의 핵심입니다.**
>
> STEP 1이 끝나면 **백엔드는 이미 진행 과정을 보내고 있습니다.** (F12 → Network 탭에서 확인 가능)
> 화면이 안 보여줄 뿐입니다. STEP 2에서 화면이 그걸 그립니다.
>
> **프론트가 똑똑해진 게 아니라 백이 더 알려준 것입니다.**
> "프론트에 기능이 생겼다"의 정체가 대부분 이것입니다.

## 5. 그래프 구조 — 3개 단어

**랭그래프(LangGraph)의 아이디어는 AI의 작업 흐름을 순서도로 그리는 것**입니다.

- **노드(Node)** = 작업 한 단계 (파이썬 함수 하나)
- **엣지(Edge)** = 화살표, "다음엔 이거 해"
- **상태(State)** = 노드들이 주고받는 공유 메모장

이 셋만 알면 랭그래프의 80%입니다.

```
       ┌───────────────────────────────────┐
       │                                   │ (도구 결과를 들고 다시 판단)
 [시작]─▶[think: 판단]──조건분기──▶[action: 행동 = 도구 실행]
                          │
                          └──(도구 필요 없음)──▶[끝]
```

> ★ **에이전트를 에이전트답게 만드는 건 딱 두 개입니다.**
> ① **갈림길(조건 분기)** ② **되돌아가는 화살표(반복)**
>
> 챗봇에는 이 둘이 없습니다.

**두 갈래를 다 봐야 이해한 것입니다.**

```
💬 B-2041 언제 들어와?          💬 안녕?
  🧠 [think] 판단 중...           🧠 [think] 판단 중...
  ⚙️  [action] 도구 실행         ✅ 답변: 안녕하세요! ...
  🔧 [도구] lookup('B-2041')
  🧠 [think] 판단 중...          ← action 없이 끝. 이게 갈림길의 다른 쪽 길
✅ 답변: 재고 0개, 납기 3주
```

## 6. 준비물

- [ ] 2-1단계 결과물 (없으면 `01-web-basic/example/`에서 복사해도 됩니다)
- [ ] Python 3.10 이상
- [ ] 라이브러리 세 개: `fastapi`, `uvicorn`, `langgraph`

**API 키도, 계정도, 인터넷도 필요 없습니다.**

### 가상환경(`.venv`)이 뭔가요? 왜 만드나요?

라이브러리를 설치하면 보통 **컴퓨터 전체가 공유하는 파이썬**에 설치됩니다.
프로젝트가 여러 개면 서로 다른 버전을 요구해 충돌합니다.

**가상환경**은 프로젝트 폴더 안에 **이 프로젝트만 쓰는 독립된 파이썬 공간**을 만드는 것입니다.
요리마다 조리대를 따로 쓰는 것과 같습니다.

```powershell
python -m venv .venv          # 최초 1회만
.venv\Scripts\Activate.ps1    # 작업할 때마다 매번 → 앞에 (.venv) 표시가 뜨면 성공
```

> ⚠️ 가상환경 없이 `pip install`만 하면 **"저번엔 됐는데 지금은 에러 나요"** 사고의 대표 원인이 됩니다.
> `.venv`는 통째로 지웠다 다시 만들면 그만이라 **실수해도 되돌리기 쉽습니다.**
> (`.venv` 폴더는 `.gitignore`에 등록돼 깃허브에 올라가지 않습니다)

## 7. 배포 = URL이 생기는 것 🟢

- `localhost` = 내 컴퓨터. **노트북을 끄면 서비스도 죽습니다**
- 남이 쓰게 하려면 24시간 켜진 컴퓨터(서버)에 올려야 합니다 → 그게 배포

> **실제 배포는 하지 않습니다.** 무료 배포 서비스도 계정 가입·카드 등록에서 시간을 다 잡아먹습니다.
> `uvicorn` 로컬 실행까지만 하고, 배포는 **개념 설명 + Agent Room 실물 시연**으로 대체합니다.

## 8. 내 도메인에 적용하기 🟢

같은 껍데기가 모든 도메인을 받아냅니다. **바꾸는 건 세 칸뿐입니다.**

| 도메인 | 화면 입력 라벨 | 도구가 찾아올 것 (`data.py`) | 에이전트가 만들 결과 |
|---|---|---|---|
| 영업 | "고객사 정보" | 과거 제안서 · 단가표 | 제안서 초안 |
| 행정 | "민원 내용" | 부서별 업무분장표 | 담당부서 분류 + 회신문 |
| 연구 | "논문 URL" | 내 서지 목록 | 요약 + 선행연구 정리 |
| 제조 | "품번" | 재고 · 납기 테이블 | 납기 회신문 |
| 인사 | "이력서 텍스트" | 직무기술서 | 적합도 요약 |
| 마케팅 | "제품 설명" | 브랜드 톤 가이드 | 카피 3안 |
| **내 도메인** | | | |

> 🎯 **맨 아랫줄을 채우세요. 코딩보다 이게 더 중요합니다.**
> 가운데 칸이 안 떠오르면, **그게 진짜 과제입니다.**
