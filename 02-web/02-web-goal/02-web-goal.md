# 2-2단계 — 도달점: 에이전트 껍데기(Shell) 만들기

🟡 **전원 권장** — 코드는 전부 만들어져 있습니다. **실행하고, 한 줄 바꾸고, 관찰**하면 됩니다.

## 1. 이 단계의 목적

원우마다 도메인은 다르지만, **에이전트를 실제로 써먹으려 할 때 막히는 지점은 전원 동일**합니다.

> "코드는 돌아간다. 그런데 이걸 어떻게 **우리 팀이 쓸 수 있는 물건**으로 만들지?"

이 단계는 그 물음에 대한 **최소 정답 하나**를 손에 쥐어주는 것이 목적입니다.
완성된 서비스를 만드는 게 아니라, **내용물만 갈아끼우면 어떤 도메인에도 맞는 껍데기**를 만들고
거기에 **동작하는 에이전트를 한 번 끼워봅니다.**

```
심장 (도메인마다 다름)  →  껍데기 : 화면 + 서버 + 도구 데이터
뼈대 (원우 전원 공통)   →  내용물 : 파이썬 · LLM · 에이전트 구조
```

## 2. 만들 것

**2-1단계에서 만든 `index.html`을 그대로 가져와** 뒤에 서버와 에이전트를 붙입니다. 새 화면은 없습니다.

```
[브라우저]  index.html
     │  ① fetch()로 질문을 JSON에 담아 보냄
     ▼
[서버]     app.py   POST /api/ask
     │  ② run_agent(질문) 호출
     ▼
        run_agent()
          1차: 가짜 응답          ← 연결이 됐는지만 확인
          2차: LangGraph 에이전트  ← 도구를 쓰고 판단을 반복
     │  ③ 답변 문자열 반환
     ▼
[브라우저]  결과 영역에 표시
```

### 파일 구성

| 파일 | 구분 | 역할 |
|---|---|---|
| [`index.html`](index.html) | 프론트 | 2-1단계 결과물 **그대로** |
| [`style.css`](style.css) | 프론트 | **한 줄도 안 바뀜** |
| [`script.js`](script.js) | 프론트 | 가짜 응답 → `fetch` 호출로 교체 ← **여기만 바뀜** |
| [`app.py`](app.py) | 백엔드 | FastAPI. 엔드포인트 **하나**뿐 |
| [`agent.py`](agent.py) | 에이전트 | LangGraph 그래프 + 도구. `run_agent()`가 여기 |
| [`requirements.txt`](requirements.txt) | 설정 | 설치할 라이브러리 목록 |

> ★ **프론트 3개 중 2개가 그대로라는 게 요점입니다.**
> "화면과 두뇌는 분리되어 있다"는 말이 바로 이것입니다.

## 3. 준비 — 파이썬 환경과 키 🟢

서버를 띄우는 순간부터 **파이썬 환경**과 **API 키**가 필요합니다.
[2-0단계 도구 지도](../00-web-tools/00-web-tools.md)에서 개념으로 본 것을 여기서 실제로 설정합니다.

### 3-1. 가상환경(`.venv`)이 뭔가요? 왜 만드나요?

라이브러리를 설치하면 보통 **컴퓨터 전체가 공유하는 파이썬**에 설치됩니다.
문제는 프로젝트가 여러 개면 서로 다른 버전을 요구할 수 있다는 것입니다.
(A 프로젝트는 `langgraph 1.0`, B 프로젝트는 `2.0` 필요 → 컴퓨터엔 하나만 설치 가능 → 충돌)

**가상환경(`.venv`)** 은 프로젝트 폴더 안에 **이 프로젝트만 쓰는 독립된 파이썬 공간**을 만드는 것입니다.
비유하자면, 여러 요리를 한 조리대에서 하면 재료가 섞이니 **요리마다 조리대를 따로 쓰는 것**입니다.

> ⚠️ **가상환경 없이 그냥 `pip install`만 하면**
> - 전역 파이썬에 계속 쌓여서, 어떤 프로젝트가 뭘 쓰는지 알 수 없게 됨
> - 버전 충돌 → **"저번엔 됐는데 지금은 에러 나요"** 사고의 대표 원인
> - 반면 `.venv`는 통째로 지웠다 다시 만들면 그만 → **실수해도 되돌리기 쉬움**

`.venv` 폴더는 (`.env`처럼) **깃허브에 올라가지 않습니다** (`.gitignore`에 등록됨).

### 3-2. API 키란?

AI 회사 서버에 "나 사용 허가 받은 사람이야"라고 보여주는 **출입증**입니다.

- Martial Agent가 수업 시간에 **새로 발급해서 전달**하고, **수업이 끝나면 폐기**합니다
- 그래서 키를 코드에 직접 쓰지 않고 **`.env` 파일**에 넣습니다 (`.env`는 깃허브에 안 올라감)

### 3-3. 설정 순서

**전부 리포 맨 위 폴더에서 실행합니다.**

```powershell
# 1. .env.example을 복사해 .env로 이름 변경 후, 받은 키를 붙여넣기
#    GOOGLE_API_KEY=AIza...받은키...

# 2. 가상환경 만들기 (최초 1회만)
python -m venv .venv

# 3. 가상환경 활성화 (작업할 때마다 매번)
.venv\Scripts\Activate.ps1
#    → 터미널 맨 앞에 (.venv) 표시가 뜨면 성공!

# 4. 라이브러리 설치
pip install -r 02-web/02-web-goal/requirements.txt

# 5. 서버 실행
uvicorn app:app --reload --app-dir 02-web/02-web-goal
```

브라우저에서 **http://localhost:8000** 접속.

> ⚠️ **절대 하면 안 되는 것**: API 키를 코드 파일에 직접 쓰고 깃허브에 푸시하기.
> 봇들이 깃허브를 24시간 뒤지며 유출된 키를 수집합니다. 키는 항상 `.env`에!

## 4. 1차 — 서버 붙이기 🟡

[`agent.py`](agent.py) 맨 위가 `USE_AGENT = False` 로 되어 있습니다.
**AI 없이 가짜 응답만 돌려주는 상태**입니다. 먼저 이 상태로 연결부터 확인합니다.

### ① 화면과 두뇌는 분리되어 있고, JSON으로 대화한다

`fetch()`가 하는 일입니다. 이걸 모르면 나중에 어떤 툴·서비스를 쓰더라도 조립을 못 합니다.
2-1단계의 `setTimeout` 딜레이 자리가 **실제 네트워크 대기**로 바뀐 것을 눈으로 봅니다.

> 🎯 **실습 — 이 단계의 하이라이트:** F12 → **Network 탭**을 열어두고 버튼 누르기.
> 목록에 `ask` 가 새로 생깁니다. 클릭하면
> **Payload** 탭에 내가 보낸 것 `{"question": "..."}`,
> **Response** 탭에 서버가 준 것 `{"answer": "..."}` 이 보입니다.

### ② 파이썬 함수 하나를 서버가 감싼다

```python
@app.post("/api/ask")     # ← 이 한 줄이 함수를 "주소가 있는 것"으로 만든다
```

3~5단계에서 만들 모든 파이썬 코드가 이 방식으로 세상에 나갈 수 있습니다.

### ③ API 키는 절대 프론트엔드에 두지 않는다

**초심자 사고 1순위**이고, 심장의 앞 절반인 **깃허브 파트와 직결**됩니다.

- `index.html`이나 `script.js`에 키를 적으면 → 접속자 누구나 볼 수 있음
- 키를 커밋하면 → 깃허브에 영구 기록. 지워도 히스토리에 남음
- 그래서 키는 **서버 쪽 `.env`** 에 두고, `.gitignore`에 `.env`를 넣는다

> 브라우저는 질문만 보내고, 키를 쥔 채 Gemini를 호출하는 건 [`agent.py`](agent.py)입니다.
> **사용자는 키를 볼 방법이 없습니다.** 이게 구조로 보이는 자리입니다.

### ④ 배포 = URL이 생기는 것 🟢

- `localhost` = 내 컴퓨터. **노트북을 끄면 서비스도 죽는다**
- 남이 쓰게 하려면 24시간 켜져 있는 컴퓨터(서버)에 올려야 한다 → 그게 배포

> **실제 배포는 하지 않습니다.** 무료 배포 서비스는 계정 가입·카드 등록에서 시간을 다 잡아먹습니다.
> `uvicorn` 로컬 실행까지만 하고, 배포는 **개념 설명 + Agent Room 실물 시연**으로 대체합니다.

## 5. 2차 — `run_agent()` 채우기: 도구를 쓰는 에이전트 🟡

[`agent.py`](agent.py)의 `USE_AGENT` 를 **`True`로 바꾸고 저장**하세요. 그게 전부입니다.
(`--reload` 옵션 덕에 서버가 알아서 다시 뜹니다)

**이 한 줄이 껍데기에 내용물이 들어가는 순간입니다.**

### 5-1. 챗봇이 아니라 에이전트인 이유 🟢

| | 챗봇 | 에이전트 |
|---|---|---|
| 동작 | 질문 → 답 (1회성) | **판단 → 행동 → 확인 → 다시 판단** (반복) |
| 도구 | 없음 (아는 것만 말함) | **도구를 직접 씀** (조회·계산·검색) |
| 비유 | 안내데스크 직원 | 일을 통째로 맡기는 비서 |

**도메인 적용에서 이 차이가 결정적입니다.** Gemini는 우리 회사 재고도, 우리 부서 규정도,
내 연구실 서지 목록도 모릅니다. 그걸 **찾아오는 도구**를 쥐여줘야 쓸모가 생깁니다.

### 5-2. LangGraph 3개 단어 🟢

**랭그래프(LangGraph)** 의 핵심 아이디어는 **AI의 작업 흐름을 순서도(그래프)로 그리는 것**입니다.

- **노드(Node)** = 작업 한 단계 (파이썬 함수 하나)
- **엣지(Edge)** = 화살표, "다음엔 이거 해"
- **상태(State)** = 노드들이 주고받는 공유 메모장

이 셋만 알면 랭그래프의 80%입니다.

### 5-3. 그래프 구조 — 갈림길과 반복

에이전트를 에이전트답게 만드는 건 딱 두 개입니다: **① 갈림길(조건 분기)** 과 **② 되돌아가는 화살표(반복)**.

```
       ┌──────────────────────────────┐
       │                              │ (도구 결과 들고 다시 판단)
[시작]─▶[think: 판단]──조건분기──▶[action: 행동(도구 실행)]
                          │
                          └──(도구 필요 없음)──▶[끝]
```

[`agent.py`](agent.py)에서 이 세 부분을 찾아보세요.

```python
# ① 도구(Tool): 에이전트가 손에 쥐는 "연장"
@tool
def lookup(code: str) -> str:
    """품번으로 재고 수량과 납기를 조회한다. 예: 'A-1023'"""
    return str(INVENTORY.get(code, "해당 품번을 찾을 수 없습니다"))

# ② 조건 분기: think 다음의 갈림길 — 도구 쓸까? 말까?
def route(state):
    if state["messages"][-1].tool_calls:   # AI가 "도구 써줘"라고 했으면
        return "action"                    #   → 행동 노드로
    return END                             # 아니면 답이 다 나온 것 → 끝

# ③ 그래프 조립
graph.add_edge(START, "think")
graph.add_conditional_edges("think", route, {"action": "action", END: END})
graph.add_edge("action", "think")   # 행동 → 다시 판단 (반복!)
```

### 5-4. 예제 도구 — 우리 조직 데이터 조회

**각자 갈아끼우는 건 사실상 이 딕셔너리 하나입니다.**

```python
# 우리 조직 데이터 (지금은 가짜. 나중엔 Supabase 같은 DB에서 읽어옴)
INVENTORY = {
    "A-1023": {"재고": 48, "납기": "3일"},
    "B-2041": {"재고": 0,  "납기": "3주"},
    "C-3077": {"재고": 5,  "납기": "1주"},
}
```

`"B-2041 언제 들어와?"` 라고 물으면 터미널에 이렇게 찍힙니다.

```
💬 질문: B-2041 언제 들어와?
  🧠 [think] 판단 중...
  ⚙️  [action] 도구 실행
  🔧 [도구] lookup('B-2041') 실행
  🧠 [think] 판단 중...
✅ 답변: B-2041은 현재 재고가 없으며, 납기는 3주입니다.
```

**판단 ↔ 행동이 한 바퀴 왕복**한 게 보이시나요?
챗봇이면 재고를 모른 채 그럴듯한 숫자를 지어냅니다.

> 🔎 **직접 실험**: 도구가 필요 없는 질문(`"안녕?"`)을 넣어보세요.
> `[action]` 없이 `[think]` 한 번에 끝나는 것(= 갈림길의 **다른 쪽 길**)을 확인할 수 있습니다.
>
> 🔎 **실험 2**: `lookup`의 docstring을 `"""조회."""` 로 뭉개보세요.
> AI가 도구를 안 쓰거나 엉뚱할 때 씁니다. **설명문이 곧 성능입니다.**

### 5-5. 대화를 이어가려면 — 웹에서의 기억 🔴

터미널 프로그램이라면 `while` 루프로 계속 질문을 받습니다. **웹에서는 그 루프가 필요 없습니다.
버튼을 누를 때마다가 한 턴**이고, 브라우저가 루프 역할을 대신합니다.

대신 문제가 하나 생깁니다. 매 요청이 서로를 모른다는 것입니다.
AI가 `"어떤 품번을 말씀하시나요?"` 라고 **되물었을 때** 이어서 답할 방법이 없어집니다.

```python
APP = graph.compile(checkpointer=MemorySaver())        # 대화 기록 저장소
{"configurable": {"thread_id": "web-demo"}}            # 대화방 번호
```

**`thread_id`가 같으면 이전 대화가 이어집니다.** 지금은 고정값 하나로 두고,
"사용자가 여러 명이면 사람마다 다른 값이 필요하다 → 그래서 로그인과 DB가 필요해진다"까지만 짚습니다.
([2-0단계](../00-web-tools/00-web-tools.md)의 Supabase가 여기서 필요해집니다.)

> ⚠️ `MemorySaver`는 **서버를 끄면 사라집니다.** 진짜 서비스가 되려면 DB에 저장해야 합니다.

## 6. 내 도메인에 적용하기 🟢

같은 껍데기가 모든 도메인을 받아냅니다. **바꾸는 건 세 칸뿐입니다.**

| 도메인 | 화면 입력 라벨 | 도구(`@tool`)가 찾아올 것 | 에이전트가 만들 결과 |
|---|---|---|---|
| 영업 | "고객사 정보" | 과거 제안서·단가표 | 제안서 초안 |
| 행정 | "민원 내용" | 부서별 업무분장표 | 담당부서 분류 + 회신문 |
| 연구 | "논문 URL" | 내 서지 목록 | 요약 + 선행연구 정리 |
| 제조 | "품번" | 재고·납기 테이블 | 납기 회신문 |
| 인사 | "이력서 텍스트" | 직무기술서 | 적합도 요약 |
| 마케팅 | "제품 설명" | 브랜드 톤 가이드 | 카피 3안 |
| **내 도메인** | | | |

> 🎯 **실습: 맨 아랫줄을 채우세요. 코딩보다 이게 더 중요합니다.**
> 여기서 "우리 조직 데이터를 어디서 가져올 것인가"가 안 떠오르면, **그게 진짜 과제입니다.**

### 바이브코딩 미션 🟡

> "`02-web/02-web-goal/agent.py`를 참고해서 ○○하는 도구를 추가해줘.
> 모델은 gemini-2.5-flash-lite, API 키는 `.env`의 `GOOGLE_API_KEY`를 써."

1. `INVENTORY`를 **내 도메인 데이터**로 바꾸기
2. 도구를 **하나 더** 추가하기 (예: 글자 수 세기, 날짜 계산)
3. 화면 라벨과 안내 문구를 내 도메인에 맞게 바꾸기
4. 결과에 복사 버튼 붙이기

**미션의 진짜 목표:** 결과 코드에서 **노드가 몇 개이고 화살표가 어떻게 이어졌는지** 스스로 짚어 설명하기.

---

## 7. 실전 서비스와 비교 — Agent Room 🟢

관점은 **"우리는 프론트만이고 저긴 백엔드가 있다"(단절)가 아니라 "구조가 같고 규모만 크다"(확장)** 입니다.

| | 내가 만든 껍데기 | Agent Room ([agentroom.cloud](https://agentroom.cloud)) |
|---|---|---|
| 화면 | `index.html` 한 장 | Django 템플릿 + 바닐라 JS |
| 서버 | FastAPI, 엔드포인트 1개 | Python + Django |
| AI | LangGraph 노드 2개 + 도구 1개 | LangGraph 다중 에이전트 + Gemini |
| 대화 기억 | `MemorySaver` (서버 끄면 사라짐) | PostgreSQL에 영구 저장 |
| 로그인 | 없음 (`thread_id` 고정) | Django 세션/쿠키 인증 |
| 배포 | `localhost` | Gunicorn → AWS EC2 |
| 결제 | 없음 | Paddle 웹훅 |

> 오른쪽 열은 전부 왼쪽 열에 **하나씩 더한 것**입니다. 없던 개념이 아니라 같은 자리의 확장판입니다.

## ✅ 체크포인트

**껍데기** 🟢
- [ ] 가상환경(`.venv`)을 왜 만드는지 설명할 수 있다
- [ ] `uvicorn`으로 서버를 띄우고 `localhost:8000`에 접속했다
- [ ] F12 Network 탭에서 요청/응답이 오가는 걸 봤다
- [ ] API 키를 왜 `.env`에 넣는지, 왜 프론트엔드에 두면 안 되는지 설명할 수 있다
- [ ] `localhost`와 배포의 차이를 설명할 수 있다

**내용물** 🟡
- [ ] `USE_AGENT`를 `True`로 바꿔 진짜 답변을 받아봤다
- [ ] 노드 / 엣지 / 상태를 한 문장씩으로 설명할 수 있다
- [ ] 챗봇과 에이전트의 차이를 설명할 수 있다
- [ ] **갈림길(조건 분기)** 과 **반복 엣지**를 코드에서 짚을 수 있다
- [ ] 도구가 필요한 질문과 필요 없는 질문을 넣어 두 갈래를 모두 봤다

**적용** 🟢
- [ ] **6절 표의 맨 아랫줄(내 도메인)을 채웠다**
