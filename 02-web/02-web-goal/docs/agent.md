## 1. 만들 것 — 파일 여섯 개

2-1에서 셋을 가져오고, 이 단계에서 셋을 새로 만듭니다.

| 파일 | 어디서 | 역할 |
|---|---|---|
| `index.html` | 2-1에서 복사 | 화면 (STEP 5·6에서 크게 늘어남) |
| `style.css` | 2-1에서 복사 | 겉모습 (STEP 3~6에서 덧붙임) |
| `script.js` | 2-1에서 복사 | 화면 동작 (STEP 3부터 고침) |
| `data.js` | **새로** | 더미 사내 데이터 — 내 도메인이 들어가는 곳 |
| `brain.js` | **새로** ← ★ | **판단** — 진짜 LLM이 들어갈 자리 |
| `agent.js` | **새로** ← ★ | **그래프** — 노드 · 엣지 · 상태 · 조건분기 · 반복 |

> ⚠️ **파이썬 파일은 하나도 만들지 않습니다.** `requirements.txt`도 만들지 않습니다.

### 왜 파일을 이렇게 나누나 ★

```
script.js  "화면"      — 그리는 법을 안다. 에이전트 안은 모른다
agent.js   "흐름"      — 그래프를 안다. 판단은 brain에게 맡긴다
brain.js   "판단"      — 판단만 한다. 도구를 직접 실행하지는 않는다
data.js    "데이터"    — 값만 갖고 있다
```

**각 파일이 자기 일만 압니다.** 이게 중요한 이유:

- 3~5단계에서 진짜 LLM을 붙일 때 → **`brain.js` 하나만 바꿉니다**
- 자기 도메인으로 갈아끼울 때 → **`data.js` 하나만 바꿉니다**
- 나머지는 한 줄도 안 고칩니다

## 2. 주고받는 데이터의 모양 — ★ 이 계약이 전부입니다

### `brain.js`의 `decide()`가 돌려주는 것 — 둘 중 하나

```js
{ tool_calls: [{ name: "lookup", args: { code: "A-1023" } }] }   // "도구를 써줘"
{ content: "재고는 48개입니다." }                                  // "답이 다 나왔어"
```

> ★ **진짜 LLM도 정확히 이 두 가지 중 하나를 돌려줍니다.**
> OpenAI든 Gemini든 `tool_calls` 아니면 `content` 입니다.
> 그래서 나중에 `brain.js` 안만 갈아끼우면 나머지가 그대로 돕니다.

### 도구가 돌려주는 것

```js
{ text: "A-1023 (알루미늄 브라켓)\n  재고 48개 · 납기 3일", sources: ["재고표 / A-1023"] }
```

`sources`가 화면의 **근거 칩**이 됩니다. 도구가 결과와 함께 출처를 같이 내놓는 게 핵심입니다.

### 화면이 부르는 것 — `agent.js`의 `Backend`

```js
Backend.login(name)                → { token, user, thread_id }
Backend.chat(question, threadId)   → { answer, steps, sources }
Backend.history(threadId)          → { messages }
Backend.reset(threadId)            → { ok }
```

> ★ **이 네 줄이 진짜 서비스에서는 그대로 서버 주소가 됩니다.**
> `Backend.chat(...)` → `fetch("/api/chat", ...)` 로 바꾸는 것이 전부입니다.
> 그래서 지금 서버 없이 만들어도 나중에 옮길 때 구조를 다시 짜지 않습니다.

## 3. 클로드가 넘지 말아야 할 선 🚫

**STEP 0에서 이 절을 `work/CLAUDE.md`로 만들어둡니다.** 대화가 길어져도 규칙을 잊지 않게 하는 장치입니다.

| 금지 | 이유 |
|---|---|
| `server.py` · `app.py` · FastAPI · uvicorn · **파이썬 파일 전부** | 2단계는 **브라우저 안에서 끝납니다** |
| `fetch` · `axios` · `XMLHttpRequest` | 부를 서버가 없습니다 |
| `requirements.txt` · `pip install` · `npm install` | 설치할 게 없습니다 |
| 진짜 LLM 호출 · API 키 · `.env` | 3~5단계 |
| React · Vue · Tailwind · CDN `<script src="http...">` | 부품이 안 보이게 됩니다 |
| 파일 합치기 (`<style>`·`<script>` 인라인) | 넷/여섯으로 나뉜 게 교재입니다 |
| `innerHTML`로 사용자 입력 넣기 | 태그로 해석됩니다. **`textContent`를 쓸 것** |
| 한 번에 여러 STEP 진행 | 뭐 때문에 뭐가 달라졌는지 안 보입니다 |
| `brain.js`가 도구를 직접 실행 | 판단과 행동은 **분리**되어야 합니다 (그래야 LLM으로 교체됨) |

**지킬 것**

- 바닐라 HTML · CSS · JavaScript만. **랜선을 뽑아도 끝까지 돌아가야 합니다.**
- 주석은 **한국어로 넉넉하게.** 특히 **무엇이 더미인지 반드시 명시.**
- 파일 맨 위 주석에 이걸 넣을 것
  - `agent.js` — 그래프 그림 (`think` / `action` / 조건분기 / 반복 화살표)
  - `brain.js` — **"여기가 진짜 LLM이 들어갈 자리다. 지금은 규칙으로 흉내낸다. 3~5단계에서 이 파일만 바꾸면 나머지는 그대로 돌아간다."**
- **모르는 걸 지어내지 않습니다.** 없는 품번은 "등록되지 않았다"고 답합니다.

> 🎯 **결론:** 업무에 쓸 수 있는 AI와 못 쓰는 AI의 차이가 이 칩 하나입니다.
> **틀릴 수 있다는 것보다, 뭘 보고 답했는지 모르는 게 더 위험합니다.**

## STEP 5 — 한 화면으로 펴기 🟡 ← ★ 이 화면의 설계 의도

> **바뀌는 것:** `index.html`, `style.css`, `script.js`
> 채팅창 하나였던 화면을 **네 덩어리가 보이는 한 페이지**로 바꿉니다.

```
index.html을 한 화면짜리 대시보드로 바꿔줘. prd.md 4절의 그림대로:

왼쪽 칸 (좁게)
  📦 사내 데이터  — data.js의 INVENTORY를 표로 그린다.
                   품번 줄을 누르면 lookup 도구가 바로 실행되고 결과가 보인다
  🔧 도구        — 품번 입력칸 + [lookup] [list_codes] 버튼.
                   실행 결과를 검은 콘솔 모양 상자에 보여준다
  🧠 걸어간 길    — 그래프 그림(시작 → think ⇄ action → 끝)과 밟은 단계 목록.
                   대화를 보내면 밟은 노드가 순서대로 켜지게 해줘 (setTimeout으로 재생)

오른쪽 칸 (넓게, 세로로 꽉)
  💬 대화        — 지금 있는 채팅창 그대로

★ 이 화면의 핵심을 주석과 화면 문구로 반드시 짚어줘:
    🔧 도구 패널 : 어떤 도구를 쓸지 내가 고른다  → 그냥 프로그램
    💬 대화      : 어떤 도구를 쓸지 쟤가 고른다  → 에이전트
  같은 lookup() 함수를 부른다. 고르는 주체만 다르다.

각 덩어리 제목 옆에 [진짜] / [더미] 딱지를 달아줘.
화면이 좁으면 한 줄로 쌓이게 (CSS grid + media query).
```

**확인**

- [ ] 왼쪽 표에서 **`B-2041`을 누르면** 도구 결과가 바로 나온다
- [ ] 오른쪽에 **`B-2041 언제 들어와?`** 를 치면 **같은 결과**가 나온다
- [ ] 그때 그래프에서 `think → action → think` 가 순서대로 켜진다
- [ ] `안녕?` 을 치면 **`action`이 안 켜진다** ← ★

> 🎯 **결론:** 왼쪽과 오른쪽이 같은 함수를 부릅니다. **다른 건 누가 골랐느냐 뿐입니다.**
> 이 문장을 말로 외우지 말고, 두 번 눌러서 몸으로 확인하세요.

## STEP 6 — 더미 로그인과 대화방 🟡

> **바뀌는 것:** `index.html`, `script.js`, `style.css`

```
머리말에 이름 입력칸과 [입장] 버튼을 넣어줘.

- 이름을 넣고 [입장]하면 Backend.login(name)으로 토큰·사용자·대화방을 받는다
- 들어오면 입력칸이 사라지고 "이름 (부서) · 대화방" 표시와 [새 대화] [나가기] 버튼이 뜬다
- 로그인 전에는 채팅 입력만 잠그고, 왼쪽 데이터·도구는 그냥 쓸 수 있게 둔다
- 사용자마다 thread_id가 달라져서 대화가 섞이지 않아야 한다

★ 로그인 상태는 그냥 변수 하나에만 담아줘.
  localStorage에도 쿠키에도 저장하지 마. 새로고침하면 바로 풀리는 게 맞다.
  "세션이 끝나면 풀린다"가 무슨 뜻인지 주석으로 설명해줘.

★ 실패라는 게 없다. 이름을 적으면 무조건 통과다.
  ⚠️ 이건 진짜 인증이 아니라 "자리"만 만든 더미라고 화면에도 주석에도 분명히 적어줘.
```

**확인**

- [ ] 이름을 넣고 [입장]하면 **바로** 채팅이 열린다 (실패·확인 없음)
- [ ] [나가기] 후 **다른 이름**으로 들어가면 **대화가 비어 있다** ← 방이 나뉜 것
- [ ] 원래 이름으로 다시 들어가면 **그 방의 대화가 남아 있다**
- [ ] **`F5` 새로고침 → 로그인도 대화도 사라진다** ← 브라우저 안에만 있었으니까

> 🎯 **결론 — 데이터가 어디에 사는가**
>
> | 사는 곳 | 새로고침 | 다른 사람도 봄 |
> |---|---|---|
> | 브라우저 메모리 (**지금 여기**) | ❌ 사라짐 | ❌ |
> | 서버 메모리 | ✅ 남음 | ✅ |
> | 데이터베이스 | ✅ | ✅ |
>
> 아랫줄로 내려가려면 **서버**가 필요합니다.
> 그 모습은 [`../example/app.py`](../example/app.py)에 **읽을거리로** 넣어뒀습니다.
> 2단계에서는 만들지 않습니다. **에이전트가 어떻게 도는지**가 이 단계의 목표니까요.
