## STEP 1 — 🔧 백엔드: 에이전트 넣기 🟡

> **이번에 생기는 것:** `agent.py`, `brain.py`, `data.py`
> **화면은 한 줄도 안 고칩니다.**

```
work/ 에 agent.py, brain.py, data.py 를 만들고, app.py가 규칙표 대신
에이전트를 부르도록 고쳐줘. requirements.txt에 langgraph를 추가해줘.

★ script.js, index.html, style.css 는 절대 건드리지 마. 이번엔 백엔드만이다.

[data.py]  02-spec.md 6절의 INVENTORY 딕셔너리를 그대로

[agent.py] 02-spec.md 3절의 그래프를 LangGraph로
  - State: messages, steps, sources — 셋 다 Annotated[list, add] (이어붙이기)
  - 노드 think: brain.decide()를 부르고 결과를 messages와 steps에 남긴다
  - 노드 action: think가 지시한 도구를 실행하고 결과를 messages/steps/sources에 남긴다
  - 조건분기 route: 마지막 메시지에 tool_calls가 있으면 "action", 없으면 END
  - 엣지: START→think, think→(조건분기), action→think  ← 되돌아가는 화살표
  - 도구는 지금은 lookup 하나만. 02-spec.md 5절의 모양대로
    ({"text":..., "sources":[...]} 를 돌려주고, 없는 품번은 지어내지 않는다)
  - run_agent(question, history) → {"answer", "steps", "sources"}
  - 파일 맨 위에 그래프 그림을 주석으로 그려줘

[brain.py] 02-spec.md 4절의 계약과 판단 규칙대로 decide(messages)
  ★ 이 파일 맨 위에 큰 주석으로 반드시 적어줘:
    "여기가 진짜 LLM이 들어갈 자리다. 지금은 규칙으로 흉내낸다.
     3~5단계에서 이 파일만 바꾸면 나머지는 그대로 돌아간다."

[app.py]
  - RULES 표를 지우고 run_agent()를 부른다
  - 응답을 {"answer", "steps", "sources"} 로 내보낸다  ← steps는 아직 화면이 안 씀
  - 대화 기록에도 steps, sources를 함께 저장한다

LLM 라이브러리(langchain-google-genai, openai 등)는 설치도 import도 하지 마.
```

**확인** — 서버 재시작 후 http://localhost:8000

- [ ] `B-2041 언제 들어와?` → **재고 0개, 납기 3주**라는 답이 온다 ← ★
- [ ] `안녕?` → 도구 없이 바로 답한다
- [ ] `Z-9999?` → "등록되지 않은 품번" — **숫자를 지어내지 않는다** ← ★
- [ ] **터미널**에 이렇게 찍힌다:
  ```
  💬 질문: B-2041 언제 들어와?
    🧠 [think] 판단 중...
    ⚙️  [action] 도구 실행
    🔧 [도구] lookup('B-2041')
    🧠 [think] 판단 중...
  ```
- [ ] **F12 → Network 탭 → `chat` → Response**: `steps` 배열이 **이미 와 있다** ← ★
- [ ] 그런데 **화면에는 안 보인다** ← 정상입니다. 다음 STEP에서 그립니다

> 🎯 **이번 STEP의 결론 두 가지**
>
> 1. **화면을 한 줄도 안 고쳤는데 답이 똑똑해졌습니다.** 화면과 두뇌는 정말로 분리되어 있습니다.
> 2. **터미널에서 `think → action → think` 왕복**을 보세요. **판단 ↔ 행동이 한 바퀴 돈 것**입니다.
>    챗봇이면 재고를 모른 채 그럴듯한 숫자를 지어냅니다.

**실험:** `안녕?` 을 넣으면 `[action]` 없이 `[think]` 한 번에 끝납니다.
**이게 갈림길의 다른 쪽 길입니다.** 이 두 갈래를 다 봐야 조건분기를 이해한 것입니다.

## STEP 2 — 🖥 프론트: 진행 과정 보여주기 🟡

> **이번에 생기는 것:** 답변 아래 "에이전트가 한 일" 접기/펴기
> **백엔드는 한 줄도 안 고칩니다.** 데이터는 STEP 1부터 이미 오고 있었습니다.

```
script.js와 style.css를 고쳐서, 서버가 준 steps를 답변 아래에 표시해줘.

★ app.py, agent.py, brain.py, data.py 는 절대 건드리지 마. 이번엔 프론트만이다.

- 답변 말풍선과 진행 과정을 묶는 .bot-block 상자를 만든다
- 진행 과정은 <details> 태그로 접기/펴기. summary는 "에이전트가 한 일 N단계"
  기본은 접혀 있을 것
- 안에는 <ol> 순서 목록. 각 항목 앞에 노드 이름 배지(.node)를 붙인다
  think 와 action 의 배지 색을 다르게 할 것
- <details>는 브라우저가 이미 아는 태그라 접고 펴는 데 JS가 필요 없다는 걸
  주석으로 짚어줘
```

**확인**

- [ ] 답변 아래 **`▸ 에이전트가 한 일 3단계`** 가 보인다
- [ ] 클릭하면 펴진다:
  ```
  1. [think ] 도구가 필요하다고 판단 → lookup
  2. [action] lookup(code='B-2041') 실행
  3. [think ] 도구 결과를 정리해 답변 작성
  ```
- [ ] `안녕?` 은 **1단계**만 나온다 (`think` 하나) ← ★
- [ ] 백엔드 파일들의 수정 시각이 그대로다 (안 건드렸다는 뜻)

> 🎯 **이번 STEP의 결론 — 이 단계 전체에서 가장 중요한 문장입니다.**
>
> **프론트가 똑똑해진 게 아닙니다. 백엔드가 더 많이 알려준 것입니다.**
>
> STEP 1에서 `steps`는 이미 Network 탭에 와 있었습니다. 화면이 안 그렸을 뿐입니다.
> **"프론트에 기능이 생겼다"의 정체가 대부분 이것입니다.**
>
> 그리고 이제 **챗봇과 에이전트의 차이가 눈에 보입니다.** 판단하고, 행동하고, 다시 판단합니다.

## STEP 3 — 🔧 백엔드: 도구 추가 + 근거 🟡

> **이번에 생기는 것:** 도구 하나 더, 그리고 `sources`(근거)
> **화면은 안 고칩니다.**

```
agent.py에 도구를 하나 더 추가하고, brain.py가 그걸 쓸 수 있게 해줘.

★ 프론트(script.js, index.html, style.css)는 절대 건드리지 마.

[agent.py]
- list_codes() 도구 추가: 인자 없이 등록된 품번 전체 목록을 돌려준다
- 두 도구 모두 {"text": ..., "sources": [...]} 를 돌려주도록 통일
  lookup → sources: ["재고표 / A-1023"]
  list_codes → sources: ["재고표 / 전체"]
  없는 품번이면 sources는 빈 리스트
- run_agent가 sources의 중복을 제거해서 돌려주게 해줘

[brain.py]
- "목록", "전체", "리스트", "뭐가 있" 같은 말이 나오면 list_codes를 부른다
- 품번이 여러 개면 lookup을 여러 번 부른다 (tool_calls 배열에 여러 개)
```

**확인**

- [ ] `품번 목록 보여줘` → 세 품번이 다 나온다
- [ ] `A-1023이랑 C-3077 재고 알려줘` → **두 개가 한 번에** 조회된다
- [ ] 진행 과정에 `action`이 **두 줄** 나온다 ← ★
- [ ] Network 탭 Response에 `sources` 배열이 와 있다 (화면엔 아직 안 보임)

> 🎯 **이번 STEP의 결론:** **도구를 더하는 건 파이썬 함수를 하나 더 쓰는 일입니다.**
> 그게 전부입니다. 자기 도메인 도구를 추가하는 것도 똑같습니다.

## STEP 5 — 🔧 백엔드: 더미 로그인 + 대화방 🟡

> ⚠️ **이번에 만드는 인증은 가짜입니다.** 진짜 인증의 **"자리"** 만 만듭니다.

```
app.py에 더미 로그인과 대화방(thread) 분리를 넣어줘.

★ 프론트는 절대 건드리지 마. (다음 STEP에서 한다)
★ 진짜 인증은 만들지 마. 비밀번호도, JWT 라이브러리도, OAuth도 쓰지 마.

[data.py]
- 더미 사용자 몇 명 (김영업→영업팀, 박행정→총무팀, 그 외는 게스트)

[app.py]
- POST /api/login  { name } → { token, user, thread_id }
  · 아무 이름이나 통과한다
  · ★ 토큰과 thread_id에는 이름을 그대로 쓰지 말고, 영문·숫자로 된 짧은 아이디로 바꿔라
    (hashlib로 md5 앞 8자리 정도). HTTP 헤더에 한글이 들어가면 브라우저 fetch가
    요청 자체를 거부하기 때문이다. 이 이유를 주석으로 꼭 적어줘.
- 대화 저장소를 리스트 하나에서 {thread_id: [...]} 딕셔너리로 바꾼다
- /api/chat, /api/history, /api/reset 모두 thread_id를 받고,
  Authorization 헤더에 "Bearer dummy-token-..." 이 없으면 401을 돌려준다
- ⚠️ 이게 왜 가짜 인증인지, 진짜라면 뭐가 더 필요한지 주석으로 분명히 적어줘
```

**확인** — 화면은 아직 안 고쳤으니 **채팅이 깨집니다. 그게 정상입니다.**

- [ ] 브라우저에서 메시지를 보내면 **빨간 오류 말풍선**이 뜬다 (401)
- [ ] F12 → Network 탭에서 `chat` 요청이 **401**로 표시된다 ← ★

> 🎯 **이번 STEP의 결론:** 서버가 **문을 걸어 잠갔습니다.**
> 토큰 없이는 아무것도 못 합니다. 다음 STEP에서 화면이 열쇠를 들고 오게 만듭니다.
>
> **인증의 뼈대는 이게 전부입니다.**
> ① 로그인하면 토큰을 준다 → ② 이후 요청마다 토큰을 달고 온다 → ③ 서버가 확인한다
> 진짜 인증은 여기에 **비밀번호 해시 · 서명 · 만료 · HTTPS**가 붙을 뿐입니다.
> 그래서 대부분 직접 안 만들고 Supabase나 Google OAuth를 씁니다.

## STEP 6 — 🖥 프론트: 로그인 화면 + 대화 이어가기 🟡

```
index.html, style.css, script.js를 고쳐서 로그인 화면을 만들고 채팅을 되살려줘.

★ 백엔드는 절대 건드리지 마.

[index.html]
- 로그인 화면 <section id="login-view"> 추가:
  제목, 이름 입력칸, [시작하기] 버튼
  ⚠️ "진짜 로그인이 아닙니다" 안내 문구를 화면에 반드시 표시할 것
- 채팅 화면은 <main id="chat-view"> 로 감싸고, 헤더에 [새 대화] 버튼과
  현재 사용자 표시(id="who")를 넣는다

[script.js]
- 로그인하면 받은 { token, user, thread_id } 를 localStorage에 저장하고 채팅 화면으로 전환
- 이후 모든 요청에 Authorization: Bearer <token> 헤더를 붙인다
- /api/chat 과 /api/history 에 thread_id를 함께 보낸다
- 페이지가 뜰 때 localStorage에 세션이 있으면 바로 채팅 화면으로,
  없으면 로그인 화면으로
- 401이 오면 localStorage를 비우고 로그인 화면으로 돌아간다
- [새 대화] 버튼: /api/reset 호출 후 대화를 다시 불러온다
- 기록 복원 시 assistant 메시지의 steps와 sources도 함께 그린다

[style.css]
- 로그인 화면 스타일과 .hidden 클래스 추가
```

**확인**

- [ ] 새로고침하면 **로그인 화면**이 먼저 뜬다
- [ ] `김영업` 으로 들어가서 대화 → 정상 동작
- [ ] **`F5` 새로고침** → 로그인 화면 없이 바로 채팅, **대화도 그대로** ← ★
- [ ] 복원된 대화에도 **진행 과정과 근거 칩이 그대로** 보인다
- [ ] **[새 대화]** 를 누르면 비워진다
- [ ] **다른 사람으로 로그인해보기** — Console 탭에서:
  ```js
  localStorage.clear(); location.reload();
  ```
  `박행정` 으로 들어가면 **대화가 비어 있다** ← ★ 대화방이 나뉜 것
- [ ] 다시 `김영업` 으로 들어가면 **아까 대화가 그대로 있다** ← ★
- [ ] F12 → Network 탭 → `chat` → **Headers**에 `Authorization: Bearer dummy-token-...` 이 보인다

> 🎯 **이번 STEP의 결론:** 이제 **서비스처럼 보입니다.**
> 그런데 실제로 늘어난 건 **토큰 하나와 대화방 번호 하나**뿐입니다.
>
> ⚠️ 서버를 껐다 켜면 대화가 사라집니다. **서버 메모리이지 DB가 아니기 때문입니다.**
> 여기가 [2-0단계 도구 지도](../../00-web-tools/00-web-tools.md)의 **Supabase**가 필요해지는 자리입니다.

## 여유가 있으면 — 추가 미션 🟡

1. **`data.py`의 `INVENTORY`를 내 도메인 데이터로 바꾸기** ← 가장 중요
2. 도구를 **하나 더** 추가 (예: 담당팀으로 품번 찾기, 재고 부족 품목만 추리기)
3. `brain.py`의 판단 규칙에 **내 도메인 표현** 추가하기
4. 화면 제목·라벨·안내 문구를 내 도메인에 맞게
5. 답변에 **복사 버튼** 붙이기

**미션의 진짜 목표:** 결과 코드에서 **노드가 몇 개이고 화살표가 어떻게 이어졌는지**
스스로 짚어 설명하기.

## 🔴 개발 트랙 실험

1. **`brain.py`의 품번 정규식을 망가뜨려 보세요.** 도구를 안 쓰고 엉뚱하게 답합니다.
   → **진짜 LLM에서는 도구의 설명문(docstring)이 이 역할을 합니다. 그래서 "설명문이 곧 성능"입니다.**
2. **`agent.py`의 `action → think` 엣지를 지우고 `action → END`로 바꿔보세요.**
   도구는 실행되는데 답변이 안 나옵니다. → **되돌아가는 화살표가 왜 필요한지** 알게 됩니다.
3. **`brain.py`가 항상 `lookup`을 부르게 해보세요.** `안녕?` 에도 도구를 씁니다.
   → **판단 없는 에이전트는 그냥 파이프라인입니다.**
