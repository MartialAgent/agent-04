## 1. 파일 구성

작업 폴더는 `02-web/02-web-goal/work/` 입니다.

| 파일 | 어디서 왔나 | 역할 |
|---|---|---|
| `index.html` | 2-1에서 복사 | 화면 뼈대 (+ STEP 6에서 로그인 화면 추가) |
| `style.css` | 2-1에서 복사 | 겉모습 (+ 진행과정·근거칩·로그인 스타일 추가) |
| `script.js` | 2-1에서 복사 | 동작 (STEP 2·4·6에서 표시 기능 추가) |
| `app.py` | 2-1 `server.py`의 후신 | 서버. **에이전트를 부르기만** 함 |
| `agent.py` | **새로** | 그래프 — 노드·엣지·상태 |
| `brain.py` | **새로** | 판단 (규칙 기반 더미 두뇌) |
| `data.py` | **새로** | 더미 사내 데이터 |
| `requirements.txt` | 2-1에서 복사 | + `langgraph` 한 줄 추가 |

### 왜 파일을 이렇게 나누나 ★

```
app.py    "서버"      — HTTP를 안다. 에이전트 안은 모른다
agent.py  "흐름"      — 그래프를 안다. 판단은 brain에게 맡긴다
brain.py  "판단"      — 판단만 한다. 도구를 직접 실행하지는 않는다
data.py   "데이터"    — 값만 갖고 있다
```

**각 파일이 자기 일만 압니다.** 이게 중요한 이유:

- 3~5단계에서 진짜 LLM을 붙일 때 → **`brain.py` 하나만 바꿉니다**
- 자기 도메인으로 갈아끼울 때 → **`data.py` 하나만 바꿉니다**
- 나머지는 한 줄도 안 고칩니다

## 2. 전체 흐름

```
[브라우저] index.html + script.js
     │  ① fetch("/api/chat")  { question, thread_id }  + 토큰
     ▼
[서버]    app.py
     │  ② run_agent(질문, 대화기록)
     ▼
[에이전트] agent.py — 그래프를 돈다
     │       think → (도구 필요?) → action → think → ...
     │       판단은 brain.py, 데이터는 data.py
     │  ③ { answer, steps, sources }
     ▼
[서버]    app.py — 대화방에 저장하고 JSON으로 내보냄
     ▼
[브라우저] 답변 말풍선 + 진행 과정 + 근거 칩
```

## 3. 그래프 구조 ★ 이 단계의 핵심

**랭그래프(LangGraph)의 아이디어는 AI의 작업 흐름을 순서도로 그리는 것**입니다.
단어 셋만 알면 80%입니다.

| 단어 | 뜻 | 여기서는 |
|---|---|---|
| **노드(Node)** | 작업 한 단계 = 파이썬 함수 하나 | `think`, `action` |
| **엣지(Edge)** | 화살표. "다음엔 이거 해" | `START→think`, `action→think` |
| **상태(State)** | 노드들이 주고받는 공유 메모장 | `messages`, `steps`, `sources` |

```
       ┌───────────────────────────────────┐
       │                                   │ (도구 결과를 들고 다시 판단)
 [시작]─▶[think: 판단]──조건분기──▶[action: 행동 = 도구 실행]
                          │
                          └──(도구 필요 없음)──▶[끝]
```

> ★ **에이전트를 에이전트답게 만드는 건 딱 두 개입니다.**
> ① **갈림길(조건 분기)** — 도구를 쓸지 말지 갈라지는 곳
> ② **되돌아가는 화살표(반복)** — `action → think`
>
> 챗봇에는 이 둘이 없습니다. 질문 → 답, 끝입니다.

### 상태(State)

| 항목 | 담기는 것 | 왜 필요한가 |
|---|---|---|
| `messages` | 대화 (사용자 / 에이전트 / 도구) | 문맥 |
| `steps` | 밟은 단계 기록 | **화면에 진행 과정을 보여주려고** |
| `sources` | 참조한 데이터 출처 | **화면에 근거를 보여주려고** |

세 항목 모두 **"덮어쓰지 말고 뒤에 이어붙이는"** 규칙(`Annotated[list, add]`)을 씁니다.

> `steps`와 `sources`는 챗봇이라면 필요 없는 항목입니다.
> **에이전트가 무슨 일을 했는지 밖에서 볼 수 있게** 일부러 상태에 넣은 것입니다.

### 메시지 모양

```python
{"role": "user",      "content": "B-2041 언제 들어와?"}
{"role": "assistant", "content": "",   "tool_calls": [{"name": "lookup", "args": {"code": "B-2041"}}]}
{"role": "tool",      "name": "lookup", "content": "B-2041 (스테인리스 힌지) 재고 0개 ..."}
{"role": "assistant", "content": "조회 결과입니다. ...", "tool_calls": []}
```

### 갈림길 규칙

```
think 다음:
   마지막 메시지에 tool_calls 가 있으면  →  action
   없으면                               →  끝
```

## 4. 두뇌(`brain.py`)의 계약 ★

`decide(messages)` 는 **둘 중 하나**를 돌려줍니다. **이 계약이 전부입니다.**

```python
{"tool_calls": [{"name": "lookup", "args": {"code": "A-1023"}}]}   # "도구를 써줘"
{"content": "조회 결과입니다. ..."}                                  # "답이 다 나왔어"
```

> ★ **진짜 LLM(Gemini·GPT)도 정확히 이 두 가지 중 하나를 돌려줍니다.**
> 그래서 나중에 이 파일만 갈아끼우면 나머지가 그대로 돌아갑니다.
> **이걸 "인터페이스를 맞춰둔다"고 합니다.**

### 판단 규칙 (더미)

| 상황 | 결정 |
|---|---|
| 직전 메시지가 도구 결과 | 결과들을 모아 문장으로 정리 → `content` |
| 입력에 품번 형태(`A-1023`, `b 2041`)가 있음 | `lookup` 호출 (여러 개면 여러 번) |
| 입력에 "목록/전체/리스트/뭐가 있" | `list_codes` 호출 |
| 인사말 | 도구 없이 답 |
| 감사 표현 | 도구 없이 답 |
| 그 외 | 도구 없이 "무엇을 찾아드릴까요" 안내 |

> ⚠️ 규칙 기반이라 **틀립니다.** 그래서 진짜 모델이 필요한 것이고, 그게 3~5단계입니다.
> 지금은 **"판단하는 자리가 있다"** 는 사실만 확인하면 됩니다.

## 5. 도구(Tool)

도구는 **그냥 파이썬 함수**입니다. 특별한 게 없습니다.

| 이름 | 인자 | 하는 일 |
|---|---|---|
| `lookup` | `code: str` | 품번으로 재고·납기 조회 |
| `list_codes` | 없음 | 등록된 품번 전체 목록 |

**돌려주는 모양 (고정)**

```python
{"text": "화면에 보여줄 결과 문자열", "sources": ["재고표 / A-1023"]}
```

- 없는 품번이면 `"등록되지 않은 품번입니다"` 를 돌려준다. **지어내지 않는다**
- `sources`는 "이 답이 어디서 나왔는지". 없으면 빈 리스트
- 도구가 실행될 때 터미널에 `🔧 [도구] lookup('A-1023')` 처럼 찍는다

> ★ 진짜 서비스라면 이 함수 안이 DB 조회나 사내 API 호출로 바뀝니다.
> **함수의 겉모양(이름·인자·돌려주는 값)은 그대로입니다.**

## 6. 더미 데이터 (`data.py`)

```python
INVENTORY = {
    "A-1023": {"이름": "알루미늄 브라켓",   "재고": 48, "납기": "3일", "담당": "생산1팀"},
    "B-2041": {"이름": "스테인리스 힌지",   "재고": 0,  "납기": "3주", "담당": "생산2팀"},
    "C-3077": {"이름": "고무 개스킷",       "재고": 5,  "납기": "1주", "담당": "생산1팀"},
}
```

**원우가 갈아끼우는 건 사실상 이 딕셔너리 하나입니다.**
`B-2041`의 재고가 0인 건 의도적입니다. "없다"고 답하는 걸 확인하려고요.

더미 사용자도 여기 둡니다. (`김영업` → 영업팀, `박행정` → 총무팀, 그 외는 게스트)

## 7. API 계약

### ① 로그인 (STEP 5)

```
POST /api/login
요청  { "name": "김영업" }
응답  { "token": "dummy-token-u870eafe0",
       "user": { "name": "김영업", "부서": "영업팀" },
       "thread_id": "thread-u870eafe0" }
```

> ⚠️ **진짜 인증이 아닙니다.** 비밀번호도 가입도 없고, 아무 이름이나 통과합니다.

> ★ **토큰에 이름을 그대로 쓰지 않는 이유** — 실제로 만나는 함정입니다.
> HTTP 헤더에는 **영문·숫자만 안전하게** 들어갑니다.
> `Bearer dummy-token-김영업` 처럼 한글을 넣으면 브라우저 `fetch()`가 **요청 자체를 거부**합니다.
> 그래서 이름은 JSON 본문으로(본문은 UTF-8이라 한글 OK), 헤더에 실을 값은 영문 아이디로 바꿉니다.

### ② 메시지 보내기

```
POST /api/chat
헤더  Authorization: Bearer dummy-token-...
요청  { "question": "B-2041 언제 들어와?", "thread_id": "thread-u870eafe0" }
응답  {
  "answer": "조회 결과입니다. ...",
  "steps": [
    { "node": "think",  "label": "도구가 필요하다고 판단 → lookup" },
    { "node": "action", "label": "lookup(code='B-2041') 실행" },
    { "node": "think",  "label": "도구 결과를 정리해 답변 작성" }
  ],
  "sources": ["재고표 / B-2041"]
}
```

> ★ **2-1단계에서는 `answer` 하나뿐이었습니다.**
> 늘어난 두 칸(`steps`, `sources`)이 그대로 화면의 새 기능이 됩니다.

### ③ 대화 기록 / 새 대화

```
GET  /api/history?thread_id=...   →  { "messages": [...] }
POST /api/reset?thread_id=...     →  { "ok": true }
```

- `messages`의 `assistant` 항목에는 `steps`·`sources`도 함께 들어 있다 (새로고침해도 진행 과정이 복원되도록)
- 토큰이 없거나 형식이 틀리면 **401**

## 8. 화면 명세

### 로그인 화면 (STEP 6)

- 이름 입력 + [시작하기] 버튼
- ⚠️ **"진짜 로그인이 아니다"** 는 안내 문구를 화면에 **반드시 표시**
- 로그인하면 채팅 화면으로 전환. `localStorage`에 세션 저장 (새로고침해도 유지)

### 채팅 화면 — 2-1에서 늘어난 것

| 요소 | 클래스 | STEP | 내용 |
|---|---|---|---|
| 답변 덩어리 | `bot-block` | 2 | 말풍선 + 근거 + 진행과정을 묶는 상자 |
| 진행 과정 | `steps` | 2 | `<details>`로 접기/펴기. **기본은 접힘** |
| 노드 배지 | `node` | 2 | `think` / `action` 색을 다르게 |
| 근거 칩 | `chip` | 4 | `📄 재고표 / A-1023` 형태 |
| 헤더 사용자 표시 | `who` | 6 | 이름 · 부서 · 대화방 |
| [새 대화] 버튼 | `ghost` | 6 | `/api/reset` 호출 후 다시 불러오기 |

> `<details>`는 브라우저가 이미 아는 태그라 **접었다 펴는 데 JavaScript가 한 줄도 필요 없습니다.**

### 오류 처리

- 401 → `localStorage` 비우고 로그인 화면으로
- 그 외 오류 → 빨간 말풍선 + "터미널에서 uvicorn이 돌고 있는지 확인"

## 9. 기술 제약

| 항목 | 정한 것 |
|---|---|
| 프론트엔드 | 바닐라 HTML·CSS·JS. 프레임워크·CDN 금지 |
| 백엔드 | FastAPI + uvicorn + **langgraph**. 그 외 금지 |
| **LLM 라이브러리** | **금지** (`langchain-google-genai`, `openai` 등) |
| API 키 · `.env` | **없음** |
| 외부 통신 | **없음.** 인터넷이 끊겨도 끝까지 돌아가야 한다 |
| 데이터베이스 | 없음 (서버 메모리) |
| 파이썬 | 3.10 이상 |
| 주석 | 한국어로 넉넉하게. **무엇이 더미인지 반드시 명시** |
