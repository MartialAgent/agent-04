# 2단계 — 웹개발: 에이전트를 남이 쓰게 만들기

## 이 단계가 있는 이유

3~5단계에서 배울 **에이전트는 원우 전원에게 똑같습니다.** 파이썬도, 트랜스포머도, LangGraph도 도메인마다 다르지 않아요.

각자 다른 건 **그걸 누가, 어떻게 쓰느냐**입니다. 그리고 나중에 자기 도메인에 에이전트를 붙이려 할 때 전원이 똑같은 데서 막힙니다.

> "코드는 돌아간다. 그런데 이걸 어떻게 **우리 팀이 쓸 수 있는 물건**으로 만들지?"

2단계는 그 물음에 대한 최소 정답 하나를 손에 쥐어줍니다. 완성된 사이트를 만드는 게 아니라,
**내용물만 갈아끼우면 어떤 도메인에도 맞는 껍데기**를 만듭니다.

```
심장 (도메인마다 다름)  →  껍데기 : 도구 · 화면 · 서버     ← 2단계
뼈대 (원우 전원 공통)   →  내용물 : 파이썬 · LLM · 에이전트  ← 3~5단계
```

> 💡 **비개발자에게**: 이 단계가 이 수업에서 **가장 겁나 보이지만 실은 가장 안전한 구간**입니다.
> **코드를 한 줄도 타이핑하지 않습니다.** 문서를 클로드에게 읽히고, 단계별로 주문하고,
> 브라우저에서 뭐가 달라졌는지 보는 것이 전부입니다.

| **2-2** | [`02-web-goal/`](02-web-goal/02-web-goal.md) | **에이전트 붙이기** — 그 채팅창 뒤에 서버와 LangGraph 에이전트. 프론트/백 번갈아 여섯 단계 | 🟡 |

> ★ **서버가 등장하는 시점이 2-2입니다.**

> **없어서 불편해본 다음에** 붙이려고 일부러 그렇게 나눴습니다.

## 이번 개편의 핵심 — 바이브코딩으로 만듭니다

2-1과 2-2 각각의 폴더가 이렇게 나뉩니다.

| 폴더 | 무엇 | 어떻게 |
|---|---|---|
| `docs/` | **문서** — 무엇을 왜 만드는지, 어떤 순서로 시킬지 | 읽고, **클로드에게 시킨다** |
| `work/` | **작업 폴더** | 여러분이 만든 결과물이 쌓인다 |
| `example/` | **정답지** — 다 끝난 상태의 완성본 | ⚠️ 막혔을 때만 편다 |

> ⚠️ **`example/`를 먼저 열지 마세요.**
> 정답지를 먼저 보면 "만들어봤다"가 아니라 "읽어봤다"로 끝납니다.

### 왜 문서부터인가

"채팅창 하나 만들어줘"라고 하면 클로드는 만들어줍니다. 그런데 **매번 다른 걸 만들어줍니다.**
React를 쓰기도 하고, 파일을 하나로 합치기도 하고, 갑자기 로그인을 붙이기도 합니다.

그래서 실무에서는 코드를 짜기 전에 문서를 먼저 씁니다.

| 문서 | 답하는 질문 |
|---|---|
| **PRD** | **왜** 만드나, **누가** 쓰나, **무엇이** 되면 성공인가 |
| **SPEC / 지시서** | **어떻게 · 어떤 순서로** 만드나 (파일·요소 이름, 복붙용 프롬프트) |
| **CHECKLIST** | **다 됐는지** 어떻게 아나 |
| **RULES** | 클로드가 **넘지 말아야 할 선** |

2-1은 이걸 **`prd.md` · `frontend.md` 두 장**으로 접었고, 2-2는 여섯 장으로 폈습니다.
분량이 다를 뿐 답하는 질문은 같습니다.

> 💡 **이게 이 수업에서 제일 중요한 연습입니다.**
> 코드를 못 짜도 상관없습니다. **뭘 원하는지 정확히 쓸 수 있으면 만들어집니다.**

## 이 단계에 **없는** 것 — API 키도, 계정도, 인터넷도

2단계는 **처음부터 끝까지 계정 하나 없이 돌아갑니다.**

| 없는 것 | 대신 |
|---|---|
| **Gemini API 키 / LLM 호출** | 규칙 기반 더미 두뇌 (`brain.py`) — **진짜 모델은 3~5단계** |
| **사내 데이터베이스** | 더미 딕셔너리 (`data.py`) |
| **진짜 로그인 / 인증** | 이름만 적으면 통과하는 더미 |
| **배포** | `localhost` + 개념 설명 + Agent Room 실물 시연 |
| **React 등 프레임워크** | 바닐라 HTML · CSS · JS |

> **왜 이렇게 했나**
> 여기서 API 키를 요구하면 전원이 키 발급·과금·네트워크 오류에서 시간을 다 씁니다.
> 2단계의 목표는 **껍데기(구조)** 를 손에 쥐는 것이지 모델을 부르는 게 아닙니다.
>
> 그리고 나중에 진짜로 바꿀 때 **갈아끼우는 파일이 어디인지도 정확히 알게 됩니다.**
> 3~5단계에서 진짜 LLM을 붙일 때 바뀌는 건 **`brain.py` 하나뿐**입니다.

## 2단계를 마치면

🟢
- [ ] 웹 서비스에 어떤 서비스(계정)들이 필요한지, 언제 필요한지 안다
- [ ] 화면이 HTML·CSS·JavaScript 세 부품의 조합이라는 걸 손으로 확인했다
- [ ] 화면과 서버가 분리되어 있고 JSON으로 대화한다는 걸 안다
- [ ] API 키를 어디에 둬야 하는지, 왜 프론트엔드에 두면 안 되는지 안다
- [ ] **내 도메인의 입력값과 에이전트가 할 일을 한 줄로 적었다**

🟡
- [ ] 브라우저에서 내가 띄운 서버에 접속해봤다
- [ ] **PRD·SPEC 문서를 클로드에게 읽히고 단계별로 시켜봤다**
- [ ] 챗봇과 에이전트의 차이를, 화면의 "진행 과정"으로 설명할 수 있다
- [ ] **무엇이 진짜이고 무엇이 더미인지** 구분해서 말할 수 있다

🔴
- [ ] 갈림길(조건 분기)과 반복 엣지를 코드에서 짚을 수 있다
