# 2-0단계 — 웹 서비스 도구 지도

🟢 **전원** — 읽기만 합니다. 지금 가입할 것도, 코딩할 것도 없습니다.

> 코드를 짜기 전에 **계정부터 막힙니다.**
> 이 문서는 "내 에이전트를 남이 쓰게 하려면 어떤 서비스가 필요한가"의 지도입니다.

> 💡 **비개발자에게 오히려 유리한 단계입니다.** 여기서 다루는 건 기술이 아니라
> **"무엇이 얼마나 들고, 언제 필요한가"** 라는 판단 문제입니다.

---

## 1. 왜 이게 먼저인가

에이전트를 자기 도메인에 붙이려 할 때, 원우 전원이 똑같이 겪는 순서가 있습니다.

```
파이썬 코드는 돌아간다  →  그런데 남이 못 쓴다
  →  서버가 필요하다     →  계정을 만들어야 한다
  →  카드를 등록하라고 한다  →  돈이 얼마 나가는지 모르겠다
  →  키를 여기저기 적어두다 유출한다
```

**코딩이 아니라 여기서 막힙니다.** 그래서 도구 지도를 먼저 봅니다.
지금 전부 가입할 필요는 없습니다. **"이런 게 있고, 언제 필요해지는지"만 알면 됩니다.**

---

## 2. 전체 지도

사용자의 요청이 흘러가는 순서대로 배치했습니다.

```
   사용자
     │  ① 주소를 입력한다            → 도메인      : Namecheap
     ▼
  [ 도메인 → 서버 연결 ]             → DNS         : Namecheap / Cloudflare
     │
     ▼
  [ 서버 : 24시간 켜진 컴퓨터 ]      → 호스팅      : AWS / Render
     │
     ├─ ② 로그인 확인               → 인증        : Google Cloud Console / Supabase
     ├─ ③ 데이터 저장·조회          → 데이터베이스 : Supabase / AWS RDS
     ├─ ④ AI에게 물어봄             → AI API      : Gemini API
     └─ ⑤ 결제 처리                → 결제        : Paddle
     │
     ▼
  [ 위 전부의 열쇠(키·비밀번호) ]    → 비밀 관리   : Bitwarden
```

| 역할 | 대표 서비스 | 없으면 생기는 일 |
|---|---|---|
| 소스코드 보관 | **GitHub** (1단계에서 완료) | 코드가 내 노트북에만 있음 |
| 서버 | **AWS** | 내 노트북을 끄면 서비스가 죽음 |
| 데이터베이스 | **Supabase** | 새로고침하면 데이터가 사라짐 |
| 로그인 | **Google Cloud Console** | 사용자를 구분할 수 없음 |
| AI 두뇌 | **Gemini API** | 에이전트가 생각을 못 함 |
| 주소 | **Namecheap** | `13.125.xx.xx` 같은 숫자를 알려줘야 함 |
| 결제 | **Paddle** | 돈을 받을 수 없음 |
| 비밀 관리 | **Bitwarden** | 키를 잃어버리거나 유출함 |

---

## 3. 도구별 설명

### 🖥️ AWS (Amazon Web Services) — 서버 빌리기

아마존이 운영하는 클라우드입니다. **컴퓨터를 사는 대신 시간 단위로 빌려 쓰는 것**이라고 보면 됩니다.

| 서비스 | 하는 일 |
|---|---|
| **EC2** | 가상 컴퓨터 한 대. 여기에 내 파이썬 코드를 올려 24시간 돌림 |
| **S3** | 파일 창고. 이미지·문서 저장 |
| **RDS** | 관리형 데이터베이스 (백업·업데이트를 알아서 해줌) |
| **Route 53** | 도메인 연결(DNS) |

- **비용**: 가입 후 12개월 프리티어. 작은 서버 한 대는 사실상 무료 수준
- ⚠️ **주의**: 프리티어를 넘기면 과금됩니다. 가입 직후 **Billing → 예산 알림(Budget)을 5달러로 걸어두세요.** 실수로 큰 서버를 켜두고 요금 폭탄을 맞는 사고가 흔합니다.
- **언제 필요**: 실제로 남에게 서비스를 공개할 때. 수업 중엔 안 씁니다.

> Agent Room이 EC2 위에서 돌아갑니다.

---

### 🗄️ Supabase — 데이터베이스 + 로그인을 한 번에

PostgreSQL 데이터베이스에 **로그인 기능, 파일 저장, 자동 API까지 얹어서 주는 서비스**입니다.
백엔드를 처음부터 짜지 않아도 "회원가입·로그인·데이터 저장"이 해결됩니다.

- **비용**: 무료 플랜 있음. 소규모 개인 프로젝트엔 충분
- ⚠️ **주의**: 무료 프로젝트는 일정 기간 사용이 없으면 **자동 일시정지**됩니다. 수업 후 방치하면 멈출 수 있어요
- **언제 필요**: 대화 기록을 남기거나, 사용자마다 다른 데이터를 보여줘야 할 때
- **대안**: AWS RDS(직접 관리), Firebase(구글)

> 처음 만드는 개인 프로젝트라면 AWS보다 Supabase가 훨씬 빠릅니다.

---

### 🔑 Google Cloud Console — 구글 기능을 내 서비스에 붙이는 관문

구글이 제공하는 기능들을 **내 프로그램이 쓰도록 허가받는 곳**입니다.

- **OAuth 클라이언트 ID** — "구글로 로그인" 버튼을 만들려면 여기서 발급
- **API 사용 설정** — 지도, 드라이브, 캘린더 등 켜고 끄기
- **할당량(Quota)** — 얼마나 많이 호출할 수 있는지 확인

- **비용**: 콘솔 자체는 무료. 쓰는 API에 따라 과금
- ⚠️ **주의**: OAuth 설정에서 **승인된 리디렉션 URI**를 정확히 넣어야 합니다. 로그인이 안 되는 원인 대부분이 여기입니다
- **언제 필요**: 구글 로그인을 붙일 때

> Agent Room의 구글 로그인이 여기서 나옵니다.

---

### 🤖 Gemini API — 에이전트의 두뇌

구글의 AI 모델을 내 코드에서 호출하는 통로입니다. **이 수업에서 실제로 쓰는 유일한 유료성 API**입니다.

- **키 발급**: [Google AI Studio](https://aistudio.google.com)에서 가장 간단하게 받습니다 (Cloud Console을 거치는 방법도 있지만 수업에선 AI Studio)
- **비용**: 무료 등급이 있습니다. 대신 분당·일당 호출 횟수 제한
- ⚠️ **주의**: **키는 절대 프론트엔드(`index.html`, `script.js`)에 넣지 않습니다.** 접속자 누구나 볼 수 있고, 남의 키로 요금이 나갑니다. 반드시 **서버 쪽 `.env`** 에 두세요
- **언제 필요**: **2단계에서는 안 씁니다.** 2-1·2-2는 키 없이 끝까지 돌아갑니다(두뇌를 더미로 두었습니다). 진짜 모델을 부르는 건 **3~5단계**입니다
- **수업 중**: Martial Agent가 새 키를 만들어 전달하고, 수업이 끝나면 폐기합니다

> 💡 **그런데 "키를 어디에 두나"는 지금 알아둬야 합니다.**
> [2-1단계 STEP 4](../01-web-basic/docs/frontend.md)에서 F12 → Sources 탭으로
> **`data.js`가 통째로 보이는 걸** 직접 확인합니다. 거기에 키를 적으면 그 순간 유출입니다.

---

### 🔐 Bitwarden — 키와 비밀번호 보관함

여기까지 오면 계정이 **7개 이상** 생기고, API 키가 여러 개 쌓입니다.
그리고 API 키 중에는 **한 번 보여주고 다시는 안 보여주는 것**이 많습니다.

Bitwarden은 오픈소스 비밀번호 관리자입니다.

- **비용**: 개인 무료 플랜으로 항목 무제한 저장
- **쓰는 법**: 비밀번호뿐 아니라 **API 키도 "보안 메모"로 저장**해두세요
- ⚠️ **하지 말아야 할 것**: 키를 메모장·카톡·엑셀에 적어두기, 그리고 **깃허브에 커밋하기**

> 💡 **깃허브 파트와 이어지는 지점** — 키를 실수로 커밋하면 나중에 지워도 **히스토리에 영구히 남습니다.**
> 그래서 `.env` 파일을 만들고 `.gitignore`에 등록하는 것이고, 원본 키는 Bitwarden에 둡니다.
> 이 리포에도 [`.env.example`](../../.env.example)이 그 용도로 들어 있습니다.

---

### 🌐 Namecheap — 도메인 사기

`agentroom.cloud` 같은 **주소를 1년 단위로 빌리는 곳**입니다. 사는 게 아니라 임대입니다.

- **비용**: `.com` 연 10~15달러 수준. `.cloud`, `.xyz` 같은 건 더 쌉니다
- **하는 일**: 도메인 구입 → **DNS 설정**에서 내 서버 IP를 연결(A 레코드)
- ⚠️ **주의**: 첫 해만 싸고 **갱신 시 가격이 오르는** 도메인이 많습니다. 갱신가를 꼭 확인하세요
- **대안**: Cloudflare(원가 판매 + 무료 SSL/CDN), 가비아(국내)

---

### 💳 Paddle — 결제 받기

결제를 처리해주는 서비스인데, **Stripe와 성격이 다릅니다.**

| | Stripe | **Paddle** |
|---|---|---|
| 역할 | 결제 처리만 대행 | **판매자 역할까지 대행** (Merchant of Record) |
| 세금 | 내가 직접 신고 | **각국 부가세(VAT)를 대신 계산·납부** |
| 적합 | 국내 위주 | **해외 대상 판매** |

혼자서 전 세계에 서비스를 팔면 나라마다 다른 세금이 문제가 됩니다. Paddle은 그걸 대신 떠안습니다. 대신 수수료가 조금 높습니다.

- **작동 방식**: 사용자가 결제 → Paddle이 처리 → **웹훅(Webhook)** 으로 내 서버에 "결제됐다"고 알려줌 → 내 서버가 권한을 열어줌
- ⚠️ **주의**: 가입 시 사업자 심사가 있고, 승인까지 시간이 걸립니다

> Agent Room이 `agentroom.cloud/payments/webhook/` 으로 이 알림을 받습니다.

### 🧰 그 밖에 알아두면 좋은 것

| 도구 | 한 줄 설명 | 언제 |
|---|---|---|
| **Render / Vercel** | 깃허브에 push하면 알아서 배포. AWS보다 훨씬 쉬움 | 첫 배포 |
| **Cloudflare** | DNS + 무료 SSL(`https`) + 속도 향상 | 도메인 연결할 때 |
| **ngrok** | 내 노트북에서 돌아가는 걸 임시로 외부에 공개 | 잠깐 남에게 보여줄 때 |
| **Stripe** | 결제. 국내·단순 구조에 유리 | Paddle 대안 |

## 4. 언제 무엇이 필요한가

한꺼번에 다 가입하지 마세요. 순서가 있습니다.

| 시점 | 필요한 것 | 비용 |
|---|---|---|
| **1~2단계** | GitHub | 0원 |
| **3~5단계** | + Gemini API 키 | 0원 |
| 내 컴퓨터에서 만들어볼 때 | + Bitwarden | 0원 |
| 남에게 보여줄 때 | + Render 또는 AWS | 0원~ |
| 사용자 데이터를 저장할 때 | + Supabase | 0원~ |
| 로그인을 붙일 때 | + Google Cloud Console | 0원 |
| 제대로 된 주소가 필요할 때 | + Namecheap | 연 1~2만원 |
| 돈을 받을 때 | + Paddle | 수수료 |

> **가장 흔한 실수**: 아직 만들지도 않은 서비스의 도메인부터 사는 것.
> 도메인과 결제는 **사용자가 생긴 다음**입니다.

---

## 5. 공통 안전 수칙 3가지

도메인이 무엇이든 이 셋은 똑같이 적용됩니다.

1. **가입한 서비스에 결제수단을 등록했다면, 예산 알림을 반드시 건다.** (특히 AWS)
2. **키는 코드에 쓰지 않는다.** `.env` 파일 + `.gitignore`, 원본은 Bitwarden.
3. **키가 유출됐다고 판단되면 지우지 말고 폐기(revoke) 후 재발급한다.** 코드에서 지워도 이미 나간 키는 살아 있습니다.
