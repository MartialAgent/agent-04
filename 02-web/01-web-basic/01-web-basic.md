# 2-1단계 — 채팅창 만들기: HTML · CSS · JavaScript · 서버

🟡 **전원 권장** — 코드를 직접 타이핑할 일은 없습니다.
**문서를 클로드에게 읽히고, 여섯 번에 나눠 주문하고, 매번 브라우저에서 확인**하면 됩니다.

---

## 1. 이 단계의 목적

에이전트를 자기 도메인에 붙이려면, 먼저 **사람이 말을 걸고 답을 받는 화면**이 필요합니다.
그 화면은 대부분 **채팅창**입니다. ChatGPT도, Claude도, 사내 봇도 결국 같은 모양입니다.

이 단계는 그 채팅창을 **화면부터 서버까지** 직접 만들어봅니다.
목표는 "웹개발을 배운다"가 아니라 이것입니다.

> **HTML · CSS · JavaScript · 서버가 각각 무엇을 맡는지, 하나씩 붙여보며 눈으로 확인한다.**

한꺼번에 만들면 아무것도 안 남습니다. 그래서 **여섯 번에 나눠서** 만들고,
**매 단계마다 뭐가 달라졌는지 직접 봅니다.**

> 💡 **비개발자에게**: 이 단계에서 코드를 외울 필요가 전혀 없습니다.
> **"화면 = 뼈대(HTML) + 꾸미기(CSS) + 동작(JS), 그 뒤에 서버"** 이 한 줄만 남으면 성공입니다.

### 세션 흐름상 위치

```
심장 ─┬─ 깃허브 (코드를 어디에 두나)
      └─ 웹개발 ─┬─ [2-0] 도구 지도
                 ├─ [2-1] 채팅창 만들기    ← 여기
                 └─ [2-2] 에이전트 붙이기
뼈대 ─── 트랜스포머 → LLM → 에이전트
```

## 2. 폴더 구조 — 문서 / 작업 / 정답지

이번 단계부터 폴더가 셋으로 나뉩니다. **바이브코딩을 연습하기 위한 구조**입니다.

| 폴더 | 무엇 | 어떻게 |
|---|---|---|
| [`docs/`](docs/00-how-to-use.md) | **문서** — 무엇을 만들지 적힌 발주서 | 읽고, 클로드에게 시킨다 |
| [`work/`](work/README.md) | **작업 폴더** — 결과물이 쌓이는 곳 | 여러분이 만든 것이 여기 생긴다 |
| [`example/`](example/README.md) | **정답지** — 다 끝난 상태의 완성본 | ⚠️ 막혔을 때만 편다 |

> ⚠️ **`example/`를 먼저 열지 마세요.**
> 정답지를 먼저 보면 "만들어봤다"가 아니라 "읽어봤다"로 끝납니다.

### 문서 다섯 개

실무에서 코드를 짜기 전에 쓰는 문서를 그대로 축소한 것입니다.

| 문서 | 답하는 질문 |

> **문서는 그걸 못 하게 막는 장치**이고, 실무에서 PRD·SPEC을 쓰는 이유가 정확히 이것입니다.

## 3. 만들 것

```
┌──────────────────────────────────────┐
│  🤖 내 도메인 어시스턴트               │  ← 제목 (각자 바꿈)
├──────────────────────────────────────┤
│              안녕하세요  [나]  ────▶ │  ← 내 말풍선 (오른쪽)
│  ◀──── [답변]  무엇을 도와드릴까요?   │  ← 답변 말풍선 (왼쪽)
├──────────────────────────────────────┤
│  [ 메시지를 입력하세요      ] [보내기] │
└──────────────────────────────────────┘
```

파일 다섯 개. 프레임워크도, 빌드 도구도 없습니다.

## 4. 여섯 단계 — 무엇을 더하면 무엇이 달라지는가

| STEP | 더하는 것 | 그때 느껴야 하는 것 |
|---|---|---|
| **1** | HTML만 | 못생겼다. **그런데도 페이지는 존재한다** |
| **2** | CSS | HTML은 한 글자도 안 바뀌었는데 **채팅 앱처럼 보인다** |
| **3** | JavaScript | 반응은 한다. **그런데 답할 상대가 없다** |
| **4** | 가짜 답변 (프론트) | 되긴 된다. **그런데 규칙이 다 보이고 새로고침하면 사라진다** |
| **5** | **서버** | **아, 그래서 백엔드가 필요하구나** ← ★ |
| **6** | 서버가 대화 보관 | 데이터가 **어디에 사느냐**가 문제구나 |

**4 → 5로 넘어가는 순간이 이 단계 전체의 핵심입니다.**
백엔드를 "원래 있는 것"으로 외우면 안 됩니다. **없어서 불편해본 다음에** 붙입니다.

## 5. 이 단계에 **없는** 것

| 없는 것 | 이유 |
|---|---|
| **AI · LLM** | 지금은 껍데기만. 두뇌는 2-2단계 |
| **API 키 · `.env`** | 부를 데가 없으니 키도 없음. **계정에서 막히는 사람이 없도록** |
| **로그인** | 2-2단계에서 더미로 다룸 |
| **데이터베이스** | 서버 메모리로 충분. 왜 필요해지는지는 STEP 6에서 |
| **프레임워크 · CDN** | 부품이 안 보이게 됨. 이 단계의 목적과 정반대 |
| **배포** | 계정·카드 등록에서 시간을 다 씀. 개념만 |

> **인터넷이 끊겨도 이 단계는 끝까지 돌아갑니다.** 일부러 그렇게 만들었습니다.
