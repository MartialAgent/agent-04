# 2-1단계 — 채팅창 만들기: HTML · CSS · JavaScript · 더미 데이터

🟡 **전원 권장** — 코드를 직접 타이핑할 일은 없습니다.
**문서를 클로드에게 읽히고, 네 번에 나눠 주문하고, 매번 브라우저에서 확인**하면 됩니다.

---

## 1. 이 단계의 목적

에이전트를 자기 도메인에 붙이려면, 먼저 **사람이 말을 걸고 답을 받는 화면**이 필요합니다.
그 화면은 대부분 **채팅창**입니다. ChatGPT도, Claude도, 사내 봇도 결국 같은 모양입니다.

이 단계는 그 채팅창을 **브라우저 안에서만** 만듭니다. 목표는 "웹개발을 배운다"가 아니라 이것입니다.

> **HTML · CSS · JavaScript · 데이터가 각각 무엇을 맡는지, 하나씩 붙여보며 눈으로 확인한다.**

한꺼번에 만들면 아무것도 안 남습니다. 그래서 **네 번에 나눠서** 만들고,
**매 단계마다 뭐가 달라졌는지 직접 봅니다.**

> 💡 **비개발자에게**: 코드를 외울 필요가 전혀 없습니다.
> **"화면 = 뼈대(HTML) + 꾸미기(CSS) + 동작(JS) + 내용물(데이터)"** 이 한 줄만 남으면 성공입니다.

### 세션 흐름상 위치

```
심장 ─┬─ 깃허브 (코드를 어디에 두나)
      └─ 웹개발 ─┬─ [2-0] 도구 지도
                 ├─ [2-1] 채팅창 만들기    ← 여기 (화면까지)
                 └─ [2-2] 에이전트 붙이기  (서버 + 두뇌)
뼈대 ─── 트랜스포머 → LLM → 에이전트
```

---

## 2. ★ 이 단계에 서버는 없습니다

이게 2-1단계의 **가장 중요한 약속**입니다.

```
2-1 (여기)   질문 ─→ [data.js] ─→ 답          브라우저 안에서 끝
2-2          질문 ─→ [서버] ─→ [에이전트] ─→ 답   그때 파이썬이 등장
```

| 없는 것 | 대신 |
|---|---|
| **서버 · 파이썬 · FastAPI** | 없음. 2-2단계에서 붙입니다 |
| **API 호출 (`fetch`)** | 없음. 데이터는 `data.js`에 이미 있습니다 |
| **AI · LLM** | 없음. 두뇌는 2-2단계 |
| **API 키 · `.env` · 계정** | 부를 데가 없으니 키도 없습니다 |
| **로그인 · 데이터베이스** | 2-2단계에서 더미로 |
| **React · Tailwind · npm** | 바닐라 HTML · CSS · JS |

> **`index.html`을 더블클릭하면 끝입니다.** 터미널 명령이 하나도 없습니다.
> **인터넷 선을 뽑아도 끝까지 돌아갑니다.** 일부러 그렇게 만들었습니다.

## 3. 폴더 구조

| 폴더 | 무엇 | 어떻게 |
|---|---|---|
| [`docs/`](docs/prd.md) | **문서** — 무엇을 만들지 적힌 발주서 | 읽고, 클로드에게 시킨다 |
| [`work/`](work/README.md) | **작업 폴더** — 결과물이 쌓이는 곳 | 여러분이 만든 것이 여기 생긴다 |
| [`example/`](example/README.md) | **정답지** — 다 끝난 상태의 완성본 | ⚠️ 막혔을 때만 편다 |

> ⚠️ **`example/`를 먼저 열지 마세요.**
> 정답지를 먼저 보면 "만들어봤다"가 아니라 "읽어봤다"로 끝납니다.

### 문서 두 개

실무에서 코드를 짜기 전에 쓰는 문서를 그대로 축소한 것입니다.

| 문서 | 답하는 질문 |
|---|---|
| [`prd.md`](docs/prd.md) | **왜** 만드나, **누가** 쓰나, **무엇이 되면** 성공인가 (**여기부터**) |
| [`frontend.md`](docs/frontend.md) | **어떻게 · 어떤 순서로** 만드나 (복붙용 프롬프트 + 검수) |

> 💡 **왜 문서부터인가**
> "채팅창 하나 만들어줘"라고 하면 클로드는 매번 다른 걸 만들어줍니다.
> React를 쓰기도 하고, 갑자기 서버를 붙이기도 합니다.
> **문서는 그걸 못 하게 막는 장치**이고, 실무에서 PRD를 쓰는 이유가 정확히 이것입니다.

## 4. 만들 것

```
┌──────────────────────────────────────┐
│  🤖 내 도메인 어시스턴트               │  ← 제목 (각자 바꿈)
├──────────────────────────────────────┤
│              A-1023 재고?  [나]  ──▶ │  ← 내 말풍선 (오른쪽)
│  ◀── [답변]  알루미늄 브라켓 48개,    │  ← 답변 말풍선 (왼쪽)
│              납기 3일, 생산1팀        │
├──────────────────────────────────────┤
│  [ 메시지를 입력하세요      ] [보내기] │
└──────────────────────────────────────┘
```

**파일 네 개.** 프레임워크도, 빌드 도구도, 서버도 없습니다.

| 파일 | 역할 |
|---|---|
| `index.html` | 무엇이 **있는가** |
| `style.css` | 어떻게 **보이는가** |
| `script.js` | 무슨 일이 **일어나는가** |
| `data.js` | **무엇을 답하는가** ← 내 도메인이 들어가는 유일한 파일 |

> ★ 도메인이 다른 원우 스무 명이 앞의 셋은 똑같이 쓰고, **`data.js` 하나만 각자 다르게** 씁니다.
> 그게 **껍데기와 내용물의 분리**입니다.

---

## 5. 다섯 단계 — 무엇을 더하면 무엇이 달라지는가

| STEP | 더하는 것 | 그때 느껴야 하는 것 |
|---|---|---|
| **1** | HTML만 | 못생겼다. **그런데도 페이지는 존재한다** |
| **2** | CSS | HTML은 한 글자도 안 바뀌었는데 **채팅 앱처럼 보인다** |
| **3** | JavaScript | 반응은 한다. **그런데 할 말이 없다** |
| **4** | 더미 데이터 (`data.js`) | 대화가 된다. **그런데 다 보이고, 새로고침하면 사라진다** ← ★ |
| **5** | 내 도메인으로 교체 | `data.js`만 고쳤는데 **내 어시스턴트가 됐다** |

**STEP 4에서 느끼는 불편이 2-2단계로 가는 이유입니다.**
서버를 "원래 있는 것"으로 외우면 안 됩니다. **없어서 불편해본 다음에** 붙입니다.

## ✅ 체크포인트

전체 검수는 [`frontend.md`](docs/frontend.md)의 검수 체크리스트에 있습니다. 여기선 핵심만.

🟢
- [ ] HTML / CSS / JavaScript / 데이터가 각각 뭘 맡는지 한 문장씩 말할 수 있다
- [ ] F12 → Console, Sources, Network 탭을 열어봤다

🟡
- [ ] 다섯 STEP을 다 돌려 채팅창이 실제로 동작한다
- [ ] `style.css` 값을 바꿔서 화면이 변하는 걸 확인했다
- [ ] `data.js`만 고쳐 **내 업무 질문 3개**를 답하게 만들었다 (그때 `script.js`는 안 건드렸다)
- [ ] **왜 서버가 필요해지는지** 두 가지로 말할 수 있다 (감출 수 없다 / 남길 수 없다) ← ★

🔴
- [ ] `script.js`가 `data.js`의 내용을 모르는 게 왜 좋은지 설명할 수 있다
