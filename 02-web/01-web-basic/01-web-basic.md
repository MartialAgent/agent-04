# 2-1단계 기획 — 웹개발 기초: HTML · CSS · JavaScript

> **이 문서는 기획서입니다.** 실제 수업 자료와 코드는 이 기획을 바탕으로 별도 작성합니다.

---

## 1. 이 단계의 목적

에이전트를 자기 도메인에 붙이려면, 먼저 **사람이 뭔가를 입력하고 결과를 받아보는 화면**이 필요합니다.
이 단계는 그 화면을 **프론트엔드 3총사만으로 직접 만들어보는 것**이 목적입니다.

핵심은 "웹디자인을 배운다"가 아니라 **"화면은 이렇게 생긴 부품들의 조합이구나"를 손으로 확인하는 것**입니다.
30명이 각자 다른 도메인을 갖고 있어도, 만드는 화면의 뼈대는 전원 동일합니다.

### 세션 흐름상 위치

```
심장 ─┬─ 깃허브 (코드를 어디에 두나)
      └─ 웹개발 ─┬─ [2-1] 화면 만들기      ← 여기
                 └─ [2-2] 화면 뒤에 서버 붙이기
뼈대 ─── 파이썬 → 트랜스포머 → LLM → 에이전트
```

---

## 2. 만들 것 — "도메인 어시스턴트" 화면 (프론트엔드만)

입력창 하나, 버튼 하나, 결과 영역 하나짜리 단순한 한 페이지입니다.

```
┌────────────────────────────────┐
│   내 도메인 어시스턴트          │  ← 제목 (수강생이 각자 바꿈)
├────────────────────────────────┤
│  ┌──────────────────────────┐  │
│  │ (여기에 질문을 입력)      │  │  ← textarea
│  └──────────────────────────┘  │
│              [ 물어보기 ]      │  ← button
├────────────────────────────────┤
│  결과가 여기에 표시됩니다        │  ← 결과 영역
└────────────────────────────────┘
```

**중요 — 이 단계의 응답은 가짜입니다.** 버튼을 누르면 `script.js` 안에 미리 적어둔 문장이 나옵니다.
무엇을 입력하든 같은 답이 나오죠. 수강생이 "이거 진짜 AI가 아니네?"를 **스스로 느끼는 것**이 이 단계의 마지막 장면이고,
그게 곧바로 2-2단계의 출발점이 됩니다.

### 파일 구성

| 파일 | 역할 | 비유 |
|------|------|------|
| `index.html` | 뼈대 — 입력창·버튼·결과 영역이 "있다" | 건물 골조 |
| `style.css` | 꾸미기 — 색·크기·배치 | 인테리어 |
| `script.js` | 동작 — 버튼을 누르면 결과가 나온다 | 전기·수도 설비 |

## 3. 수업 진행 순서

### 3-1. 프론트엔드 vs 백엔드 (개념)

기존 [`02-web.md`](../02-web.md) 1장의 식당 비유 표를 그대로 가져옵니다.
다만 결론을 한 문장 추가합니다 — **"오늘 만드는 건 홀(프론트)뿐이고, 주방(백엔드)은 다음 단계에서 짓는다."**

### 3-2. HTML — 뼈대 세우기

- 태그 = 화면 요소 하나. `<textarea>`, `<button>`, `<div>` 세 개만 알면 이 화면이 만들어짐
- **`id` 속성**을 반드시 짚을 것 → 나중에 JavaScript가 요소를 찾아오는 이름표
- 실습: 제목 글자를 자기 도메인으로 바꿔보기

### 3-3. CSS — 꾸미기

- `색`, `여백`, `테두리` 정도만. 속성 이름을 외우게 하지 않음
- 실습: `background` 값 하나 바꾸고 저장 → 브라우저 새로고침 → 바뀌는 것 확인
- **여기서 "저장하고 새로고침" 루프를 몸에 익히는 게 진짜 목적**

### 3-4. JavaScript — 동작 붙이기

이 단계에서 가르칠 개념은 **딱 4개**입니다. 도메인 불문 전원에게 필요합니다.

| 개념 | 코드 | 뜻 |
|------|------|-----|
| 요소 잡기 | `document.getElementById("...")` | HTML에서 부품 하나 꺼내오기 |
| 이벤트 | `addEventListener("click", ...)` | "버튼이 눌리면 이걸 해라" |
| 값 읽기 | `input.value` | 사용자가 입력한 글자 가져오기 |
| 화면 바꾸기 | `result.textContent = ...` | 결과 영역에 글자 넣기 |

> **설계 포인트:** 가짜 응답을 보여주기 전에 `setTimeout`으로 1초 딜레이 + "생각 중..." 표시를 넣습니다.
> 2-2단계에서 이 딜레이 자리가 **실제 서버 대기 시간**으로 바뀌기 때문에, 구조를 미리 맞춰두는 것입니다.

### 3-5. 개발자 도구 (F12)

도메인 불문 공통 생존 기술이라 반드시 포함합니다.

- **Console 탭** — 빨간 글씨가 뜨면 그게 에러. AI에게 물어볼 때 이걸 그대로 복사해서 붙이면 됨
- **Elements 탭** — 화면의 어느 부분이 어느 태그인지 대응 확인

## 4. 바이브코딩 미션

> "01-web-basic 폴더의 페이지에 ○○를 해줘"

쉬운 순:
1. 제목과 입력창 안내 문구를 내 도메인에 맞게 바꿔줘
2. 결과 영역에 복사 버튼을 넣어줘
3. 입력이 비어 있으면 "내용을 입력하세요"라고 알려줘
4. 지금까지 물어본 질문 목록을 아래에 쌓아서 보여줘

**팁:** 한 번에 하나씩 → 브라우저에서 확인 → 마음에 안 들면 "이 부분을 이렇게 고쳐줘".

## 5. 이 단계에서 일부러 **안 하는** 것

기획상 의도적으로 뺀 항목입니다. 전부 2-2단계 소재입니다.

| 안 하는 것 | 이유 |
|---|---|
| 백엔드 / 서버 | 프론트만으로 화면이 완성된다는 걸 먼저 체감 |
| API 키, `.env` | 서버가 생겨야 "키를 어디 두나"가 질문이 됨 |
| 실제 AI 응답 | 가짜 응답의 한계를 느끼는 게 다음 단계 동기 |
| 반응형, 프레임워크(React 등) | 이 수업의 목표 밖 |
