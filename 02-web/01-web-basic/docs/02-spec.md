# SPEC — 기술 명세

> **SPEC = 명세.** PRD가 "무엇을/왜"라면 SPEC은 **"어떻게"** 입니다.
> 파일 이름, 요소 이름, 주고받는 데이터 모양처럼 **애매하면 사고가 나는 것들**을 못박습니다.
>
> 🟡 개발이 처음이면 훑고 넘어가도 됩니다. **클로드가 읽을 문서**니까요.
> 다만 3절(요소 이름표)과 4절(API 계약)은 한 번 보세요. 나중에 에러를 읽을 때 여기로 돌아옵니다.

---

## 1. 파일 구성

작업 폴더는 `02-web/01-web-basic/work/` 입니다. **파일은 다섯 개, 폴더 구조 없이 평평하게.**

| 파일 | 언제 생기나 | 역할 | 비유 |
|---|---|---|---|
| `index.html` | STEP 1 | 뼈대 — 무엇이 **있는가** | 건물 골조 |
| `style.css` | STEP 2 | 겉모습 — 어떻게 **보이는가** | 인테리어 |
| `script.js` | STEP 3 | 동작 — 무슨 일이 **일어나는가** | 전기·수도 |
| `server.py` | STEP 5 | 서버 — 답을 만들고 대화를 보관 | 주방 |
| `requirements.txt` | STEP 5 | 설치할 라이브러리 목록 | 장보기 목록 |

> 파일을 하나로 합치지 않습니다. **셋으로 나뉜 게 이 단계의 교재입니다.**

## 2. 화면 구조

```
┌──────────────────────────────────────┐
│  🤖 내 도메인 어시스턴트               │  ← header  (제목 + 부제)
├──────────────────────────────────────┤
│                                      │
│              안녕하세요  [나]  ────▶ │  ← 내 말풍선 (오른쪽, 색 채움)
│                                      │
│  ◀──── [답변]  무엇을 도와드릴까요?   │  ← 답변 말풍선 (왼쪽, 회색)
│                                      │  ← 여기만 스크롤됨
├──────────────────────────────────────┤
│  [ 메시지를 입력하세요      ] [보내기] │  ← composer (입력창 + 버튼)
└──────────────────────────────────────┘
```

- 전체는 화면 가운데 **최대 640px** 폭의 카드 한 장
- 세로로 `header` / `messages` / `composer` 세 덩어리
- **가운데 `messages`만** 남는 공간을 차지하고, 넘치면 그 안에서만 스크롤
- 새 메시지가 붙으면 항상 맨 아래로 스크롤

## 3. 요소 이름표 (`id`) — ★ 가장 중요한 표

`id`는 **JavaScript가 HTML 요소를 찾아올 때 쓰는 이름표**입니다.
`index.html`의 `id="input"` 과 `script.js`의 `getElementById("input")` 이 **짝**입니다.

**한쪽만 바꾸면 그 순간 화면이 죽습니다.** 초보자 에러 1순위입니다.

| `id` | 태그 | 역할 |
|---|---|---|
| `messages` | `<div>` | 대화가 쌓이는 상자 (처음엔 비어 있음) |
| `chat-form` | `<form>` | 입력창 + 버튼을 감싸는 것 |
| `input` | `<textarea>` | 메시지 입력창 |
| `send` | `<button>` | 보내기 버튼 |

### 클래스(`class`) 이름

| 클래스 | 붙는 곳 |
|---|---|
| `chat` | 카드 전체 |
| `chat-header` / `subtitle` | 머리말 |
| `messages` | 대화 영역 |
| `composer` | 입력 영역 |
| `bubble` | 말풍선 공통 |
| `bubble me` | 내가 쓴 말 (오른쪽) |
| `bubble bot` | 답변 (왼쪽) |
| `bubble error` | 오류 (빨강) |
| `bubble pending` | "생각 중..." (옅게) |
| `empty` | 대화가 없을 때 안내 문구 |

> 💡 `id`는 **한 페이지에 하나뿐인 것**, `class`는 **여러 개 있을 수 있는 것**에 씁니다.
> 말풍선은 계속 늘어나니까 `class`, 입력창은 하나뿐이니까 `id`입니다.

## 4. API 계약 — 화면과 서버가 주고받는 것

**계약(contract)** 이라고 부르는 이유: 양쪽이 이 모양만 지키면 서로의 코드를 몰라도 됩니다.
화면은 파이썬을 모르고, 서버는 JavaScript를 모릅니다. **JSON이라는 공용어로만 대화**합니다.

### ① 메시지 보내기

```
POST /api/chat
```

보내는 것 (요청 본문):
```json
{ "question": "안녕하세요" }
```

받는 것 (응답 본문):
```json
{ "answer": "안녕하세요! 무엇을 도와드릴까요?" }
```

### ② 대화 기록 불러오기 (STEP 6)

```
GET /api/history
```

받는 것:
```json
{
  "messages": [
    { "role": "user", "content": "안녕하세요" },
    { "role": "bot",  "content": "안녕하세요! 무엇을 도와드릴까요?" }
  ]
}
```

`role`은 `"user"`(사람) 또는 `"bot"`(서버) 둘 중 하나입니다.

### ③ 대화 지우기

```
POST /api/reset      →  { "ok": true }
```

> 🎯 **F12 → Network 탭**을 열고 메시지를 보내면 이 계약이 실제로 오가는 걸 눈으로 볼 수 있습니다.
> `Payload` = 내가 보낸 것, `Response` = 서버가 준 것.

## 5. 동작 규칙

### 보내기

1. 입력값의 앞뒤 공백을 제거한다. **비어 있으면 아무것도 하지 않는다.**
2. 내 말풍선을 즉시 오른쪽에 붙인다. (서버를 기다리지 않는다 — 답답해 보이니까)
3. 입력창을 비우고, 버튼을 비활성화한다. (연타 방지)
4. `"🤔 생각 중..."` 자리표시 말풍선을 왼쪽에 띄운다.
5. 서버에 요청을 보낸다.
6. 답이 오면 자리표시를 지우고 답변 말풍선으로 바꾼다.
7. 성공하든 실패하든 버튼을 다시 살리고 입력창에 커서를 둔다.

### 키보드

| 키 | 동작 |
|---|---|
| `Enter` | 보내기 |
| `Shift + Enter` | 줄바꿈 |

### 오류

- 서버가 꺼져 있거나 응답이 `200`이 아니면 **빨간 오류 말풍선**을 띄운다
- 문구에 **"터미널에서 uvicorn이 돌고 있는지 확인"** 을 반드시 포함한다
- 화면을 멈추지 않는다. 다시 입력할 수 있어야 한다

### 시작할 때 (STEP 6)

- `GET /api/history`를 불러 이전 대화를 복원한다
- 기록이 없으면 `"아직 대화가 없습니다"` 안내를 보여준다
- 서버에 연결이 안 되면 그것도 안내로 알린다

## 6. 서버 동작

### 답변 규칙표

서버에 **AI는 없습니다.** 키워드 표를 위에서부터 훑어 먼저 걸리는 답을 돌려줍니다.

| 입력에 들어 있으면 | 답변 |
|---|---|
| 안녕 / 하이 / hello / hi | 인사 |
| 이름 / 누구 | 자기소개 |
| 뭐 할 / 할 수 있 / 도움 / 기능 | 할 수 있는 것 안내 |
| 고마 / 감사 / thanks | 인사 |
| **어디에도 안 걸리면** | 입력을 되돌려주며 "아직 모른다"고 밝힌다 |

> ★ 마지막 줄이 중요합니다. **모르는 걸 아는 척하지 않는 것**이 이 채팅창의 유일한 미덕입니다.
> 그리고 그 한계가 2-2단계로 넘어가는 동기입니다.

### 대화 저장

- 파이썬 리스트 하나에 `{"role", "content"}` 를 순서대로 쌓는다
- **데이터베이스가 아니다.** 서버를 끄면 사라진다 → 이 한계는 2-2단계에서 다시 짚는다

### 화면 파일 서빙

- `index.html` · `style.css` · `script.js` 를 같은 서버가 함께 내려준다
- ⚠️ **정적 파일 마운트는 반드시 `server.py` 맨 아래.** `"/"` 가 모든 주소를 삼키기 때문에
  위쪽에 두면 `/api/...` 요청까지 가로챈다
