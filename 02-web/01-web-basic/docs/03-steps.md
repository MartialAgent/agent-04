# STEPS — 작업 지시서 (6단계)

> 🟡 **여기서부터 실제로 만듭니다.** 각 STEP의 회색 상자를 **그대로 복사해서** 클로드에게 붙여넣으세요.
>
> **규칙 하나: 한 번에 한 STEP.** 확인란을 눈으로 확인하기 전에는 다음으로 넘어가지 않습니다.
> 이 단계의 목적은 완성이 아니라 **"뭐가 추가되면 뭐가 달라지는지"를 보는 것**입니다.

작업 폴더: `02-web/01-web-basic/work/`

---

## STEP 0 — 준비 🟢

```
02-web/01-web-basic/docs/ 폴더의 01-prd.md, 02-spec.md, 05-claude-rules.md 를 읽어줘.

그리고 05-claude-rules.md 를 02-web/01-web-basic/work/CLAUDE.md 로 복사해줘.

아직 코드는 만들지 마. 읽고 나서 "무엇을 만들 건지"만 세 줄로 요약해줘.
```

**확인** — 클로드의 요약에 이 세 가지가 들어 있어야 합니다.
- 채팅창 하나를 만든다
- HTML → CSS → JS → 서버 순서로 여섯 번에 나눠 만든다
- AI·API 키·로그인·프레임워크는 쓰지 않는다

요약이 어긋나면 **여기서 바로잡고 시작하세요.** 나중에 고치는 것보다 100배 쌉니다.

## STEP 1 — HTML만 🟢

> **이번에 생기는 것:** `work/index.html` 파일 하나
> **아직 없는 것:** 색깔, 배치, 동작. 전부 없습니다.

```
02-web/01-web-basic/work/index.html 을 만들어줘.

지금은 HTML만이다. CSS 파일도, JS 파일도 만들지 말고, <link>나 <script> 태그도 넣지 마.
<style> 태그나 style 속성도 쓰지 마. 정말로 HTML만이어야 한다.

02-spec.md의 2절(화면 구조)과 3절(요소 이름표)을 그대로 지켜서:
- 제목과 부제가 들어간 <header>
- 대화가 쌓일 빈 <div id="messages">
- <form id="chat-form"> 안에 <textarea id="input">과 <button id="send">

각 요소가 무슨 역할인지 한국어 주석으로 설명을 달아줘.
특히 id 속성이 왜 필요한지 주석으로 짚어줘.
```

**확인** — `work/index.html`을 **더블클릭**해서 브라우저로 여세요.

- [ ] 흰 배경에 검은 글씨. **못생겼다.** ← 정상입니다
- [ ] 입력창과 버튼이 보인다
- [ ] 버튼을 눌러도 아무 일도 안 일어난다 ← 정상입니다

> 🎯 **여기서 멈추고 화면을 보세요.**
> 이게 **HTML만의 모습**입니다. 브라우저가 기본으로 주는 것 외엔 아무 꾸밈이 없습니다.
> 그런데도 **페이지는 존재합니다.** 구조는 이미 다 있습니다.

## STEP 2 — CSS 추가 🟡

> **이번에 생기는 것:** `work/style.css`
> **바뀌는 것:** `index.html`에 `<link>` **한 줄만** 추가

```
02-web/01-web-basic/work/style.css 를 만들고, index.html의 <head>에 <link>로 연결해줘.

★ 중요: index.html은 <link> 한 줄 추가 외에 절대 건드리지 마. 태그를 더하거나 지우지 마.
  "HTML은 그대로인데 화면이 달라진다"를 보여주는 게 이 단계의 목적이다.

02-spec.md의 2절 화면 구조대로:
- 가운데 최대 640px 카드, 세로로 [머리말][대화][입력창] 배치
- 대화 영역만 남는 공간을 차지하고 넘치면 그 안에서 스크롤 (flex 사용)
- 말풍선: .bubble.me 는 오른쪽 정렬 + 메인색 채움 + 흰 글씨,
          .bubble.bot 은 왼쪽 정렬 + 회색 배경
- 색은 :root 에 CSS 변수로 --main-color, --bg-color 등으로 모아둘 것

Tailwind 같은 라이브러리나 CDN은 쓰지 마. 손으로 쓴 CSS만.
각 덩어리가 무슨 일을 하는지 한국어 주석을 달아줘.
```

**확인** — 브라우저 새로고침 (`F5`).

- [ ] 갑자기 **채팅 앱처럼 보인다**
- [ ] `index.html`을 열어보면 **태그가 STEP 1과 똑같다** (`<link>` 한 줄만 늘었다)

> 🎯 **이번 STEP의 결론:** 구조(HTML)와 겉모습(CSS)은 **완전히 분리되어 있다.**
> 같은 뼈대에 다른 CSS를 씌우면 완전히 다른 서비스처럼 보입니다.

**해보기:** `style.css` 맨 위 `--main-color` 값을 `#059669`(초록)로 바꾸고 저장 → 새로고침.
**저장 → 새로고침** 이 루프를 몸에 익히는 게 진짜 목적입니다.

## STEP 3 — JavaScript 추가 🟡

> **이번에 생기는 것:** `work/script.js`
> **이번에도 안 생기는 것:** 답변. 아직 답할 상대가 없습니다.

```
02-web/01-web-basic/work/script.js 를 만들고, index.html의 body 맨 끝에 <script>로 연결해줘.

이번 단계에서 하는 일은 딱 이것뿐이다:
- 보내기 버튼을 누르거나 Enter를 치면
- 입력창의 글을 읽어서
- 내 말풍선(.bubble.me)을 대화 영역에 붙이고
- 입력창을 비운다

★ 답변은 아직 만들지 마. 내가 쓴 말만 쌓이면 된다.
  빈 입력이면 아무것도 하지 않는다. Shift+Enter는 줄바꿈이다.

말풍선을 만들 때 innerHTML 말고 textContent를 쓰고, 왜 그런지 주석으로 설명해줘.
파일 맨 위에 이 파일에서 쓰는 핵심 개념 4개(요소 잡기 / 이벤트 / 값 읽기 / 화면 바꾸기)를
주석으로 정리해줘.
```

**확인** — 새로고침 후 아무 말이나 입력하고 Enter.

- [ ] 내 말풍선이 **오른쪽에** 붙는다
- [ ] 입력창이 비워진다
- [ ] 계속 치면 계속 쌓이고, 넘치면 스크롤된다
- [ ] **답은 오지 않는다** ← 정상입니다
- [ ] F12 → Console 탭에 빨간 글씨가 없다

> 🎯 **이번 STEP의 결론:** JavaScript는 **"~하면 ~한다"** 를 담당합니다.
> HTML은 있고, CSS는 보이고, **JS는 움직입니다.** 셋의 역할이 이제 다 나왔습니다.

## STEP 4 — 가짜 답변 (프론트에서) 🟡

> **이번에 생기는 것:** 답변. 단 **`script.js` 안에** 규칙을 적어둡니다.
> 이 STEP은 **일부러 잘못 만드는 단계**입니다. 다음 STEP에서 왜 잘못인지 보여주려고요.

```
script.js 안에 간단한 답변 규칙을 넣어줘. 서버는 아직 만들지 마.

02-spec.md 6절의 규칙표대로:
- 입력에 "안녕"이 들어 있으면 인사
- "이름"이면 자기소개
- "뭐 할" / "도움" / "기능"이면 할 수 있는 것 안내
- 어디에도 안 걸리면 입력을 되돌려주며 "아직 모른다"고 솔직히 밝힐 것

내 말풍선을 붙인 뒤 "🤔 생각 중..." 자리표시를 띄우고,
setTimeout으로 0.6초 기다렸다가 답변 말풍선으로 바꿔줘.

★ 주석으로 이걸 짚어줘:
  setTimeout은 기다리는 "흉내"일 뿐이고, 다음 단계에서 이 자리가
  실제 서버 통신으로 바뀐다는 것.
```

**확인** — 새로고침 후 "안녕"이라고 쳐보세요.

- [ ] 답변이 왼쪽에 나온다
- [ ] 표에 없는 말을 치면 되돌려준다

**그리고 이 두 가지를 꼭 직접 해보세요. 이게 STEP 4의 진짜 목적입니다.**

1. **F12 → Sources 탭 → `script.js` 클릭.**
   → 답변 규칙이 **전부 그대로 보입니다.** 접속자 누구나 볼 수 있습니다.
   여기에 사내 데이터나 API 키를 적었다면 그 순간 유출입니다.

2. **`F5`로 새로고침.**
   → 대화가 **전부 사라집니다.** 브라우저 메모리에만 있었으니까요.

> 🎯 **이번 STEP의 결론 — 이 단계 전체에서 가장 중요한 문장입니다.**
>
> **프론트엔드만으로도 동작은 한다. 그런데 감출 수도 없고, 남길 수도 없다.**
> **그래서 백엔드가 필요하다.**
>
> 백엔드를 "원래 있는 것"으로 외우지 마세요. **없어서 불편해봤으니** 이제 붙입니다.

## STEP 5 — 서버 붙이기 🟡

> **이번에 생기는 것:** `work/server.py`, `work/requirements.txt`
> **이사가는 것:** STEP 4의 답변 규칙이 `script.js` → `server.py` 로

```
02-web/01-web-basic/work/server.py 와 requirements.txt 를 만들어줘.
그리고 script.js가 서버를 부르도록 고쳐줘.

[server.py]
- FastAPI + uvicorn만 쓴다. 다른 라이브러리는 쓰지 마.
- POST /api/chat : 받는 것 {"question": "..."} → 주는 것 {"answer": "..."}
- 답변 규칙은 STEP 4에서 script.js에 있던 것을 그대로 옮겨온다 (RULES 표)
- index.html, style.css, script.js도 이 서버가 함께 내려주도록 StaticFiles로 마운트
  ⚠️ 마운트는 반드시 파일 맨 아래. 이유를 주석으로 설명해줘.

[script.js]
- setTimeout + 규칙표를 지우고, fetch("/api/chat")로 교체한다
- 서버가 꺼져 있거나 오류일 때 빨간 오류 말풍선을 띄우고,
  "터미널에서 uvicorn이 돌고 있는지 확인" 문구를 포함할 것
- ★ 요소 잡기 / 이벤트 / 값 읽기 / 화면 바꾸기 4개는 그대로 두고,
  기다리는 자리만 바뀐다는 걸 주석으로 짚어줘

[requirements.txt]
- fastapi 와 uvicorn[standard] 두 줄. 실행 명령도 주석으로 적어줘.
```

**실행** — 터미널에서 (리포 맨 위 폴더):

```powershell
.venv\Scripts\Activate.ps1
pip install -r 02-web/01-web-basic/work/requirements.txt
uvicorn server:app --reload --app-dir 02-web/01-web-basic/work
```

브라우저에서 **http://localhost:8000** 접속. (`index.html` 더블클릭이 아닙니다!)

**확인**

- [ ] 채팅창이 뜨고, 메시지를 보내면 답이 온다
- [ ] **F12 → Sources 탭 → `script.js`**: 답변 규칙이 **더 이상 보이지 않는다** ← ★
- [ ] **F12 → Network 탭**을 열고 메시지 보내기 → 목록에 `chat` 이 생긴다
  - `Payload` 탭: 내가 보낸 것 `{"question": "..."}`
  - `Response` 탭: 서버가 준 것 `{"answer": "..."}`
- [ ] 터미널을 보면 요청 기록이 찍힌다
- [ ] 서버를 `Ctrl+C`로 끄고 메시지를 보내면 **빨간 오류 말풍선**이 뜬다

> 🎯 **이번 STEP의 결론 두 가지**
>
> 1. **화면과 서버는 분리되어 있고 JSON으로만 대화한다.** 서로의 코드를 모릅니다.
> 2. **서버에 있는 것은 사용자가 볼 수 없다.** 그래서 API 키·사내 데이터는 항상 서버에 둡니다.
>
> `@app.post("/api/chat")` 이 **한 줄**이 평범한 파이썬 함수를 "주소가 있는 것"으로 만듭니다.
> 3~5단계에서 만들 모든 파이썬 코드가 이 방식으로 세상에 나갑니다.

## STEP 6 — 서버가 대화를 보관 🟡

> **이번에 생기는 것:** 새로고침해도 안 사라지는 대화

```
server.py가 대화 기록을 들고 있게 하고, 화면이 시작할 때 그걸 불러오게 해줘.

[server.py]
- 파이썬 리스트 HISTORY에 {"role": "user"/"bot", "content": "..."} 를 순서대로 쌓는다
- GET  /api/history → {"messages": [...]}
- POST /api/reset   → 기록을 비우고 {"ok": true}
- ⚠️ 이건 데이터베이스가 아니라서 서버를 끄면 사라진다는 걸 주석으로 분명히 적어줘

[script.js]
- 페이지가 뜰 때 /api/history를 불러 이전 대화를 말풍선으로 복원한다
- 기록이 비어 있으면 "아직 대화가 없습니다" 안내를 보여준다
- 서버에 연결이 안 되면 그것도 안내로 알린다
```

**확인**

- [ ] 대화를 몇 개 주고받고 **`F5` 새로고침** → **대화가 그대로 남아 있다** ← ★
- [ ] 터미널에서 서버를 `Ctrl+C`로 끄고 다시 켠 뒤 새로고침 → **대화가 사라졌다**

> 🎯 **이번 STEP의 결론 — 데이터가 어디에 사는가**
>
> | 사는 곳 | 새로고침 | 서버 재시작 | 다른 사람도 봄 |
> |---|---|---|---|
> | 브라우저 메모리 (STEP 4) | ❌ 사라짐 | — | ❌ |
> | 서버 메모리 (지금) | ✅ 남음 | ❌ 사라짐 | ✅ |
> | 데이터베이스 | ✅ | ✅ | ✅ |
>
> 마지막 줄이 [2-0단계 도구 지도](../../00-web-tools/00-web-tools.md)의 **Supabase**가 필요해지는 자리입니다.
> "DB를 배워야 하니까 배운다"가 아니라, **여기까지 와서 부족해졌으니** 배우는 것입니다.

## 여유가 있으면 — 추가 미션 🟡

한 번에 하나씩, 브라우저에서 확인하면서.

1. 제목·부제·안내 문구를 **내 도메인에 맞게** 바꾸기
2. `server.py`의 규칙표에 **내 업무에서 자주 나오는 질문 3개** 추가하기
3. 답변 말풍선에 **복사 버튼** 붙이기
4. **다크 모드**로 바꾸기 (`style.css`의 `:root` 값만 건드려서)
5. 헤더에 **[대화 지우기]** 버튼 붙이기 (`/api/reset` 호출)

> 💡 이게 이 수업에서 제일 중요한 연습입니다.
> **코드를 못 짜도, 뭘 원하는지 정확히 말할 수 있으면 만들어집니다.**
