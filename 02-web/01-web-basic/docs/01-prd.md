# PRD — 내 도메인 어시스턴트 (채팅창)

> **PRD = Product Requirements Document (제품 요구사항 문서)**
> "무엇을, 왜, 누구를 위해 만드는가"를 적는 문서입니다. **코드 이야기는 한 줄도 없습니다.**
> 그래서 비개발자가 가장 잘 쓸 수 있는 문서이고, 실제로 실무에서도 기획자가 씁니다.

---

## 1. 한 줄 요약

**사람이 말을 걸면 답이 돌아오는 채팅창 하나를, 화면부터 서버까지 직접 만든다.**

---

## 2. 왜 만드나

3~5단계에서 배울 **에이전트는 원우 전원에게 똑같습니다.** 파이썬도, 트랜스포머도, LangGraph도
도메인마다 다르지 않습니다. 각자 다른 건 **그걸 누가, 어떻게 쓰느냐**입니다.

그리고 자기 도메인에 에이전트를 붙이려 할 때 전원이 똑같은 데서 막힙니다.

> "코드는 돌아간다. 그런데 이걸 어떻게 **우리 팀이 쓸 수 있는 물건**으로 만들지?"

그 물음의 답은 대부분 **채팅창**입니다.
ChatGPT도, Claude도, 사내 봇도 결국 같은 모양입니다. **입력창 + 대화 목록.**

이 단계에서는 그 채팅창을 **내용물 없이 껍데기만** 만듭니다.
두뇌(AI)는 2-2단계와 3~5단계에서 채웁니다.

---

## 3. 누가 쓰나

| 사용자 | 상황 | 원하는 것 |
|---|---|---|
| 나 (개발 중) | 만들면서 확인 | 고치면 바로 보이는 것 |
| 우리 팀 동료 | 브라우저 주소만 받음 | 설치 없이 바로 쓰는 것 |

**설치를 요구하지 않는다**가 웹으로 만드는 이유의 전부입니다.

---

## 4. 무엇이 되면 성공인가

- [ ] 브라우저에서 채팅창이 뜬다
- [ ] 메시지를 보내면 **내 말풍선이 오른쪽에** 쌓인다
- [ ] 잠시 뒤 **답변 말풍선이 왼쪽에** 나타난다
- [ ] 그 답변이 **내 브라우저가 아니라 서버에서** 온 것이다
- [ ] **새로고침해도 대화가 남아 있다**
- [ ] 만드는 사람이 **HTML / CSS / JavaScript / 서버가 각각 무엇을 맡는지** 말로 설명할 수 있다

마지막 줄이 진짜 목표입니다. 나머지는 그걸 확인하는 수단입니다.

---

## 5. 일부러 **안 하는** 것

이 목록이 PRD에서 가장 중요합니다. 안 할 것을 안 적으면 클로드가 알아서 다 넣어줍니다.

| 안 하는 것 | 이유 |
|---|---|
| **AI · LLM 호출** | 지금은 껍데기만. 두뇌는 2-2단계 |
| **API 키 · `.env`** | 부를 데가 없으니 키도 필요 없음. 계정에서 막히는 사람이 없게 |
| **로그인 · 회원가입** | 2-2단계에서 더미로 다룸 |
| **데이터베이스** | 서버 메모리로 충분. DB가 필요해지는 이유는 2-2단계에서 |
| **React · Vue 등 프레임워크** | 부품이 안 보이게 됨. 이 단계의 목적과 정반대 |
| **디자인 라이브러리 (Tailwind 등)** | CSS가 무슨 일을 하는지 안 보이게 됨 |
| **배포** | 계정 가입·카드 등록에서 시간을 다 씀. 개념만 |
| **모바일 반응형** | 목표 밖 |

> ⚠️ 클로드는 시키지 않아도 이 중 여러 개를 넣으려 합니다.
> [`05-claude-rules.md`](05-claude-rules.md)가 그걸 막는 장치입니다.

---

## 6. 만드는 순서와 그 이유

한꺼번에 만들면 **왜 그게 필요한지**를 못 느낍니다. 그래서 여섯 번에 나눠 만듭니다.

| STEP | 무엇을 더하나 | 그때 느껴야 하는 것 |
|---|---|---|
| 1 | HTML만 | "꾸미기가 없어도 페이지는 존재하는구나" |
| 2 | CSS 추가 | "HTML은 한 글자도 안 바뀌었는데 화면이 달라졌네" |
| 3 | JavaScript 추가 | "이제 반응은 하는데, 답할 상대가 없네" |
| 4 | 가짜 답변 규칙 (프론트) | "되긴 되는데 규칙이 브라우저에 다 보이고 새로고침하면 사라지네" |
| 5 | 서버 추가 | "**아, 그래서 백엔드가 필요하구나**" |
| 6 | 서버가 대화 보관 | "데이터가 어디에 사느냐가 문제구나" |

**4번에서 5번으로 넘어가는 순간이 이 단계 전체의 핵심입니다.**
백엔드를 "원래 있는 것"으로 배우면 안 됩니다. **없어서 불편해본 다음에** 붙여야 합니다.

---

## 7. 내 도메인으로 바꿀 자리

껍데기는 전원 똑같습니다. 각자 다른 건 **글자 몇 개**뿐입니다.

| 자리 | 기본값 | 내 도메인 예 |
|---|---|---|
| 제목 | 내 도메인 어시스턴트 | 영업 제안서 도우미 / 민원 분류 도우미 |
| 입력창 안내 문구 | 메시지를 입력하세요 | 고객사 정보를 붙여넣으세요 |
| 답변 규칙 (STEP 4~5) | 인사·이름·기능 안내 | 내 업무에서 자주 나오는 질문 3개 |
| **내 도메인** | | |
