## 1. 만들 것 — 파일 네 개

폴더 구조 없이 **평평하게** 놓습니다.

| 파일 | 언제 생기나 | 역할 |
|---|---|---|
| `index.html` | STEP 1 | 무엇이 **있는가** |
| `style.css` | STEP 2 | 어떻게 **보이는가** |
| `script.js` | STEP 3 | 무슨 일이 **일어나는가** |
| `data.js` | STEP 4 | **무엇을 답하는가** ← 내 도메인이 들어가는 곳 |

**파일을 하나로 합치지 않습니다. 넷으로 나뉜 게 이 단계의 교재입니다.**

> 서버 파일(`server.py`)도, `requirements.txt`도 **만들지 않습니다.**
> 2-1단계는 브라우저 안에서 끝납니다. 2-2단계도 마찬가지입니다.

## 2. 화면 구조

```
┌──────────────────────────────────────┐
│  🤖 내 도메인 어시스턴트               │  ← header  (제목 + 부제)
├──────────────────────────────────────┤
│                                      │
│              A-1023 재고?  [나]  ──▶ │  ← 내 말풍선 (오른쪽, 색 채움)
│                                      │
│  ◀── [답변]  알루미늄 브라켓 48개…     │  ← 답변 말풍선 (왼쪽, 회색)
│                                      │  ← 여기만 스크롤됨
├──────────────────────────────────────┤
│  [ 메시지를 입력하세요      ] [보내기] │  ← composer (입력창 + 버튼)
└──────────────────────────────────────┘
```

- 전체는 화면 가운데 **최대 640px** 폭의 카드 한 장
- 세로로 `header` / `messages` / `composer` 세 덩어리
- **가운데 `messages`만** 남는 공간을 차지하고, 넘치면 그 안에서만 스크롤
- 새 메시지가 붙으면 항상 맨 아래로 스크롤

## 3. 요소 이름표 (`id`) — ★ 가장 중요한 표

`id`는 **JavaScript가 HTML 요소를 찾아올 때 쓰는 이름표**입니다.
`index.html`의 `id="input"` 과 `script.js`의 `getElementById("input")` 이 **짝**입니다.

**한쪽만 바꾸면 그 순간 화면이 죽습니다.** 초보자 에러 1순위입니다.

| `id` | 태그 | 역할 |
|---|---|---|
| `messages` | `<div>` | 대화가 쌓이는 상자 (처음엔 비어 있음) |
| `chat-form` | `<form>` | 입력창 + 버튼을 감싸는 것 |
| `input` | `<textarea>` | 메시지 입력창 |
| `send` | `<button>` | 보내기 버튼 |

### 클래스(`class`) 이름

| 클래스 | 붙는 곳 |
|---|---|
| `chat` | 카드 전체 |
| `chat-header` / `subtitle` | 머리말 |
| `messages` | 대화 영역 |
| `composer` | 입력 영역 |
| `bubble` | 말풍선 공통 |
| `bubble me` | 내가 쓴 말 (오른쪽) |
| `bubble bot` | 답변 (왼쪽) |
| `bubble pending` | "생각 중..." (옅게) |
| `empty` | 대화가 없을 때 안내 문구 |

> 💡 `id`는 **한 페이지에 하나뿐인 것**, `class`는 **여러 개 있을 수 있는 것**에 씁니다.
> 말풍선은 계속 늘어나니까 `class`, 입력창은 하나뿐이니까 `id`입니다.

## 4. `data.js`의 모양 — 화면과 내용물의 계약

`script.js`는 **`data.js`가 이 모양이라고 믿고** 동작합니다. 모양만 지키면 안은 뭘 넣든 상관없습니다.

```js
// 키워드 하나라도 질문에 들어 있으면 그 답변을 쓴다. 위에서부터 먼저 걸리는 것.
const DUMMY_DATA = [
  {
    키워드: ["A-1023", "브라켓"],
    답변: "알루미늄 브라켓 (A-1023)\n재고 48개 · 납기 3일 · 담당 생산1팀",
  },
  // ... 계속
];

// 어느 키워드에도 안 걸렸을 때 쓸 답변을 만드는 함수
function 모르는답변(질문) {
  return `"${질문}"\n\n라고 하셨네요. 아직 모릅니다. ...`;
}
```

- 위에서부터 훑어 **먼저 걸리는 하나**를 씁니다
- 대소문자는 구분하지 않습니다 (`hello`와 `HELLO`가 같아야 함)
- **어디에도 안 걸리면 `모르는답변()`** — 아는 척하지 않습니다

> ★ **`script.js`는 `DUMMY_DATA`의 내용을 모릅니다.** 모양만 압니다.
> 그래서 도메인이 달라도 `script.js`는 한 글자도 안 바꿔도 됩니다.
> **이게 2-2단계에서 이 자리에 에이전트를 통째로 갈아끼울 수 있는 이유이기도 합니다.**

## 5. 동작 규칙

### 보내기

1. 입력값의 앞뒤 공백을 제거한다. **비어 있으면 아무것도 하지 않는다.**
2. 내 말풍선을 즉시 오른쪽에 붙인다.
3. 입력창을 비우고, 버튼을 잠깐 비활성화한다. (연타 방지)
4. `"🤔 생각 중..."` 자리표시 말풍선을 왼쪽에 띄운다.
5. **0.6초 기다렸다가** `data.js`에서 찾은 답변으로 바꾼다.
6. 버튼을 다시 살리고 입력창에 커서를 둔다.

> 💡 **5번의 0.6초는 왜 있나**
> 기다리는 **흉내**입니다. 지금은 기다릴 이유가 전혀 없습니다 (답이 이미 옆 파일에 있으니까).
> 2-2단계에서 이 자리가 **에이전트 호출**로 바뀝니다. 그때 자리를 미리 비워두는 것입니다.

### 키보드

| 키 | 동작 |
|---|---|
| `Enter` | 보내기 |
| `Shift + Enter` | 줄바꿈 |

## 6. 클로드가 넘지 말아야 할 선 🚫

**STEP 0에서 이 절을 `work/CLAUDE.md`로 만들어둡니다.** 대화가 길어져도 규칙을 잊지 않게 하는 장치입니다.

| 금지 | 이유 |
|---|---|
| `fetch` · `axios` · `XMLHttpRequest` | **부를 서버가 없습니다.** 데이터는 `data.js`에 이미 있습니다 |
| `server.py` · FastAPI · uvicorn · 파이썬 파일 | **2단계는 브라우저 안에서 끝납니다.** 파이썬은 3단계부터 |
| `requirements.txt` · `npm install` · `package.json` | 설치할 게 없습니다 |
| React · Vue · Tailwind · Bootstrap · CDN `<script src="http...">` | 부품이 안 보이게 됩니다. 이 단계의 목적과 정반대 |
| API 키 · `.env` · 로그인 · 데이터베이스 | 부를 데가 없으니 키도 없습니다 |
| 파일 합치기 (`<style>`·`<script>` 인라인) | 넷으로 나뉜 게 교재입니다 |
| `innerHTML`로 사용자 입력 넣기 | 사용자가 쓴 글이 태그로 해석됩니다. **`textContent`를 쓸 것** |
| 한 번에 여러 STEP 진행 | 뭐 때문에 뭐가 달라졌는지 안 보입니다 |

**지킬 것**

- 바닐라 HTML · CSS · JavaScript만. **인터넷 선을 뽑아도 끝까지 돌아가야 합니다.**
- 주석은 **한국어로 넉넉하게.** 이 코드는 읽히려고 존재합니다.
- 색은 `style.css`의 `:root`에 CSS 변수로 모읍니다 (`--main-color` 등).
- **모르는 질문에 아는 척하지 않습니다.**

## STEP 4 — 더미 데이터 붙이기 🟡 ← ★ 이 단계의 핵심

> **생기는 것:** `work/data.js` — **내 도메인이 들어가는 유일한 파일**
> **드디어 생기는 것:** 답변

```
02-web/01-web-basic/work/data.js 를 만들고, index.html에서
script.js보다 먼저 읽히도록 <script>로 연결해줘. (순서 중요)

[data.js]
frontend.md 4절의 모양 그대로 DUMMY_DATA 배열을 만들어줘.
prd.md 5절의 표에 있는 항목을 그대로 넣어줘:
- "A-1023" 또는 "브라켓" → 알루미늄 브라켓, 재고 48개, 납기 3일, 생산1팀
- "B-2041" 또는 "힌지"   → 스테인리스 힌지, 재고 없음, 납기 3주, 생산2팀
- "안녕" "하이" "hello"  → 인사
- "뭐 할" "기능" "도움"  → 지금 답할 수 있는 것 안내
그리고 어디에도 안 걸렸을 때 쓸 모르는답변() 함수.
★ 모르는 걸 아는 척하지 말고, 입력을 되돌려주면서 모른다고 밝힐 것.

[script.js]
- 내 말풍선을 붙인 뒤 "🤔 생각 중..." 자리표시를 띄우고,
  setTimeout으로 0.6초 기다렸다가 data.js에서 찾은 답변 말풍선으로 바꿔줘
- 키워드는 대소문자를 구분하지 않게 (hello와 HELLO가 같아야 함)
- ★ script.js는 DUMMY_DATA의 "내용"을 몰라야 한다. 모양만 알고 훑어야 한다.
  도메인이 바뀌어도 script.js는 안 바뀐다는 걸 주석으로 짚어줘

★ 주석으로 이것도 짚어줘:
  setTimeout은 기다리는 "흉내"일 뿐이고,
  2-2단계에서 이 자리가 에이전트 호출로 바뀐다는 것.

fetch나 서버는 여전히 쓰지 마.
```

**확인** — 새로고침 후 `A-1023 재고 얼마나 있어?` 라고 쳐보세요.

- [ ] 답변이 **왼쪽에** 나온다
- [ ] `안녕`이라고 치면 인사한다
- [ ] `hello`도 `HELLO`도 똑같이 인사한다
- [ ] 표에 없는 말(`오늘 날씨`)을 치면 **모른다고 되돌려준다**
- [ ] F12 → Network 탭에 **아무 요청도 안 생긴다** ← ★ 서버가 없다는 증거

**그리고 이 두 가지를 꼭 직접 해보세요. 이게 STEP 4의 진짜 목적입니다.**

1. **F12 → Sources 탭 → `data.js` 클릭.**
   → 데이터가 **전부 그대로 보입니다.** 접속자 누구나 볼 수 있습니다.
   여기에 사내 데이터나 API 키를 적었다면 그 순간 유출입니다.

2. **`F5`로 새로고침.**
   → 대화가 **전부 사라집니다.** 브라우저 메모리에만 있었으니까요.

> 🎯 **2-1단계 전체에서 가장 중요한 문장입니다.**
>
> **화면만으로도 동작은 한다. 그런데 감출 수도 없고, 남길 수도 없다.**
> **그래서 서버가 필요하다.**
>
> 서버를 "원래 있는 것"으로 외우지 마세요. **없어서 불편해본 것**이 남으면 됩니다.
> 2-2단계에서는 그 불편을 안은 채, 대신 **판단하는 에이전트**를 붙입니다.

## STEP 5 — 내 도메인으로 갈아끼우기 🟡 (여기까지 해야 끝입니다)

> **바뀌는 파일: `data.js` 하나.** 나머지 셋은 한 글자도 안 건드립니다.

[`prd.md` 7절](prd.md#7-내-도메인으로-바꾸기--클로드와-상의하기)에서 클로드와 상의해 정한 질문 3개를 넣습니다.

```
work/data.js 의 DUMMY_DATA를 내 도메인으로 바꿔줘.

내 도메인: (여기에 한 줄. 예 "제약회사 임상팀 시험계획서 검토")
우리 팀이 자주 묻는 질문 3개와 답:
  1. (질문) → (답)
  2. (질문) → (답)
  3. (질문) → (답)

index.html의 제목과 부제도 내 도메인에 맞게 바꿔줘.
★ script.js와 style.css는 건드리지 마. 안 건드려도 되는 게 정상이다.
```

**확인**

- [ ] 내 질문 3개가 다 답을 받는다
- [ ] **`script.js`가 한 글자도 안 바뀌었다** ← ★ 이게 "껍데기와 내용물의 분리"입니다

## ✅ 검수 체크리스트

### 결과물

🟢
- [ ] `work/` 에 파일이 **넷** 있다 (`index.html` `style.css` `script.js` `data.js`)
- [ ] **파이썬 파일이 하나도 없다** · `requirements.txt`가 없다
- [ ] `index.html` **더블클릭**만으로 채팅이 된다 (터미널 명령 없이)
- [ ] 코드 어디에도 `fetch` · `axios` · `http://` 가 없다
- [ ] F12 → Console 탭에 빨간 글씨가 없다

🟡
- [ ] 표에 없는 질문에 **모른다고 솔직히** 답한다
- [ ] `style.css`의 `--main-color`를 바꿔 화면이 변하는 걸 확인했다
- [ ] `data.js`만 고쳐 **내 업무 질문 3개**를 답하게 만들었다
- [ ] 그때 `script.js`를 **안 건드렸다**

### 이해

🟢
- [ ] HTML / CSS / JavaScript / 데이터가 각각 뭘 맡는지 한 문장씩 말할 수 있다
- [ ] F12 → Console, Sources, Network 탭을 열어봤다

🟡
- [ ] **왜 서버가 필요해지는지** 두 가지 이유로 말할 수 있다 (감출 수 없다 / 남길 수 없다)
- [ ] 지금 화면에서 **무엇이 진짜이고 무엇이 더미인지** 구분해서 말할 수 있다

🔴
- [ ] `script.js`가 `data.js`의 내용을 모르는 게 왜 좋은지 설명할 수 있다

## 막혔을 때

| 증상 | 해볼 것 |
|---|---|
| 화면이 아예 안 뜸 | `index.html`을 연 게 맞는지, 파일 경로 확인 |
| 스타일이 안 먹음 | `index.html`에 `<link ... style.css>` 줄이 있는지 |
| 버튼을 눌러도 반응 없음 | F12 → Console 탭에 빨간 글씨가 있는지 |
| `DUMMY_DATA is not defined` | `index.html`에서 `data.js`가 `script.js`**보다 먼저** 연결됐는지 |
| 클로드가 서버를 만들려 함 | `work/CLAUDE.md`가 있는지 확인. 없으면 STEP 0을 다시 |
| 15분 넘게 안 됨 | [`../example/`](../example/README.md) 정답지와 비교 |

에러를 클로드에게 줄 땐 이 형식이 가장 잘 통합니다. **요약하지 말고 빨간 글씨를 통째로** 붙여넣으세요.

```
STEP 3을 했는데 이렇게 나와.

(F12 Console의 빨간 글씨 전체 붙여넣기)

내가 기대한 건 (무엇), 실제로는 (무엇)이 일어났어.
```

> 💡 **정답지([`../example/`](../example/README.md))와 달라도 괜찮습니다.**
> 이 단계는 정답이 하나가 아닙니다. [`prd.md` 6절](prd.md#6-성공-조건--무엇이-되면-끝인가)의
> 성공 조건을 만족하면 그게 정답입니다.
> 다른 점이 있으면 **왜 그렇게 만들었는지 클로드에게 물어보세요.** 그게 제일 많이 남습니다.

## 여유가 있으면 — 추가 미션 🟡

한 번에 하나씩, 브라우저에서 확인하면서. **전부 `data.js`와 `style.css`만 건드려도 됩니다.**

1. **다크 모드**로 바꾸기 (`style.css`의 `:root` 값만 건드려서)
2. 답변 말풍선에 **복사 버튼** 붙이기
3. 첫 화면에 **예시 질문 버튼 3개** 띄우고, 누르면 그 질문이 입력되게

5. 답변에 **줄바꿈과 목록**이 예쁘게 보이도록 다듬기

> 💡 이게 이 수업에서 제일 중요한 연습입니다.
