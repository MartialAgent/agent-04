# 3단계 — 에이전트 바이브코딩: 랭그래프(LangGraph) 입문

## 1. 에이전트가 뭔가요?

| | 챗봇 | 에이전트 |
|---|---|---|
| 동작 | 질문 → 답 (1회성) | **판단 → 행동 → 확인 → 다시 판단** (여러 단계 반복) |
| 도구 | 없음 (아는 것만 말함) | **도구(연장)를 직접 씀** (계산기·검색 등) |
| 비유 | 안내데스크 직원 | 일을 통째로 맡기는 비서 |

**랭그래프(LangGraph)** 는 에이전트를 만드는 대표적인 파이썬 라이브러리입니다.
핵심 아이디어: **AI의 작업 흐름을 순서도(그래프)로 그린다.**

```
[시작] ──> [노드: 작업 한 단계] ──> [끝]
```

- **노드(Node)** = 작업 한 단계 (파이썬 함수 하나)
- **엣지(Edge)** = 화살표, "다음엔 이거 해"
- **상태(State)** = 노드들이 주고받는 공유 메모장

이 세 개만 알면 랭그래프의 80%를 아는 겁니다.

## 2. 준비: Gemini API 키 설정 🔑

이번 실습은 구글의 **Gemini 2.5 Flash-Lite** 모델을 사용합니다 (빠르고 저렴/무료 티어).

### API 키란?
AI 회사 서버에 "나 사용 허가 받은 사람이야"라고 보여주는 **출입증**입니다.
- Martial Agent가 수업 시간에 **새로 발급해서 전달**하고, **수업이 끝나면 폐기**합니다.
- 그래서 키를 코드에 직접 쓰지 않고 **`.env` 파일**에 넣습니다. (`.env`는 깃허브에 안 올라감)

### 가상환경(.venv)이 뭔가요? 왜 만들어야 하나요?

라이브러리(`langgraph` 등)를 설치하면 보통 **컴퓨터 전체가 공유하는 파이썬**에 설치됩니다.
문제는, 강의/프로젝트가 여러 개면 서로 다른 버전의 라이브러리를 요구할 수 있다는 것.
(예: A 프로젝트는 `langgraph 1.0`, B 프로젝트는 `langgraph 2.0` 필요 → 컴퓨터엔 하나만 설치 가능 → 충돌)

**가상환경(virtual environment, `.venv`)** 은 이 문제를 해결합니다:
프로젝트 폴더 안에 **이 프로젝트만 쓰는 독립된 파이썬 설치 공간**을 따로 만드는 것.
비유: 여러 요리를 한 조리대에서 하면 재료가 섞이니, 요리(프로젝트)마다 조리대(`.venv`)를 따로 쓰는 것.

> ⚠️ **가상환경 없이 그냥 `pip install`만 하면 안 좋은 이유**
> - 전역 파이썬에 이것저것 계속 쌓여서, 나중에 어떤 프로젝트가 어떤 라이브러리를 쓰는지 알 수 없게 됨
> - 다른 강의/프로젝트와 버전 충돌 → "저번엔 됐는데 지금은 에러 나요" 사고의 대표 원인
> - 문제가 생겨도 전역 환경 전체가 얽혀있어서 원인 추적이 어렵고, 지우기도 애매함
> - 반면 `.venv` 폴더는 프로젝트별로 통째로 지웠다 다시 만들면 그만 → 실수해도 되돌리기 쉬움

`.venv` 폴더 자체는 (`.env`처럼) **깃허브에 올라가지 않습니다** (`.gitignore`에 이미 등록됨).
각자 컴퓨터에서 명령어 한 줄로 다시 만들면 되기 때문에, 올릴 필요도 없고 올리면 용량만 커집니다.

### 설정 순서

1. 리포 **맨 위 폴더**에서 `.env.example` 파일을 복사 → 이름을 `.env`로 변경
2. Martial Agent가 보내준 키를 붙여넣기:
   ```
   GOOGLE_API_KEY=AIza...받은키...
   ```
3. 가상환경 만들기 (리포 맨 위 폴더에서, 최초 1회만):
   ```powershell
   python -m venv .venv
   ```
4. 가상환경 활성화 (앞으로 작업할 때마다 매번):
   ```powershell
   .venv\Scripts\Activate.ps1
   ```
   터미널 맨 앞에 `(.venv)` 표시가 뜨면 성공!
5. 활성화된 상태에서 라이브러리 설치 (이 프로젝트 전용 공간에만 설치됨):
   ```powershell
   pip install -r 03-agent/requirements.txt
   ```

> ⚠️ **절대 하면 안 되는 것**: API 키를 코드 파일에 직접 쓰고 깃허브에 푸시하기.
> 봇들이 깃허브를 24시간 뒤지며 유출된 키를 수집합니다. 키는 항상 `.env`에!

## 3. 몸풀기 — 그래프 기본 구조 (노드 1개)

먼저 랭그래프의 **뼈대**만 봅니다. [`basic_graph.py`](basic_graph.py)는 노드 1개짜리 **일직선** 그래프입니다:

```
[시작] ──> [answer 노드: 질문에 답한다] ──> [끝]
```

```python
# ① 상태: 노드들이 주고받는 공유 메모장
class State(TypedDict):
    question: str
    answer: str

# ② 노드: 작업 한 단계 = 함수 하나
def answer_node(state):
    response = llm.invoke(state["question"])   # AI에게 질문
    return {"answer": response.content}        # 메모장에 답 적기

# ③ 그래프: 순서도 조립
graph = StateGraph(State)
graph.add_node("answer", answer_node)   # 노드 등록
graph.add_edge(START, "answer")         # 시작 → answer
graph.add_edge("answer", END)           # answer → 끝
app = graph.compile()
```

실행:
```powershell
python 03-agent/basic_graph.py
```

> 💡 **그런데 이건 사실 "챗봇"입니다.** 질문 한 번 → 답 한 번 → 끝. 갈림길도, 반복도 없죠.
> 노드·엣지·상태가 뭔지 눈에 익히기 위한 몸풀기일 뿐입니다. 진짜 에이전트는 다음 단계.

## 4. 진짜 에이전트 — 도구를 쓰는 에이전트 🤖

에이전트를 에이전트답게 만드는 건 딱 두 가지가 더 붙는 겁니다:
**① 갈림길(조건 분기)** 과 **② 되돌아가는 화살표(반복)**.

[`tool_agent.py`](tool_agent.py)는 **계산 에이전트**입니다. AI가 스스로 "이건 계산기를 써야겠다"고 **판단**하고, 도구를 **행동**으로 실행하고, 결과를 **확인**한 뒤, 답이 다 나올 때까지 반복합니다.

```
       ┌──────────────────────────────┐
       │                              │ (도구 결과 들고 다시 판단)
[시작]─▶[think: 판단]──조건분기──▶[action: 행동(도구 실행)]
                          │
                          └──(도구 필요 없음)──▶[끝]
```

### 핵심 3조각

```python
# ① 도구(Tool): 에이전트가 손에 쥐는 "연장"
@tool
def calculator(expression: str) -> str:
    """수식을 계산한다. 예: '1234 * 5678'"""
    return str(eval(expression))

llm = ChatGoogleGenerativeAI(model="gemini-2.5-flash-lite").bind_tools(tools)  # "너 이 도구 쓸 수 있어"

# ② 조건 분기: think 다음의 갈림길 — 도구 쓸까? 말까?
def route(state):
    if state["messages"][-1].tool_calls:   # AI가 "도구 써줘"라고 했으면
        return "action"                    #   → 행동 노드로
    return END                             # 아니면 답이 다 나온 것 → 끝

# ③ 그래프 조립 (갈림길 + 반복이 추가된 게 핵심)
graph.add_edge(START, "think")
graph.add_conditional_edges("think", route, {"action": "action", END: END})  # 갈림길!
graph.add_edge("action", "think")   # 행동 → 다시 판단 (반복!)
```

### 실행해보기 🎯

```powershell
python 03-agent/tool_agent.py
```

실행하면 먼저 **이 에이전트가 어떻게 구성되어 있는지** 안내가 뜨고, 그다음 질문을 입력받습니다.
`1234 곱하기 5678은?` 이라고 쳐보면, 노드가 도는 모습이 **실시간으로, 한 줄씩** 그대로 찍힙니다:

```
============================================================
🔧 에이전트 구성 안내
============================================================
  모델      : gemini-2.5-flash-lite
  도구 목록 : ['calculator']
  노드      : think(판단) → action(도구 실행)
  흐름      : START → think ⇄ action → END
              (think가 도구 필요 없다고 판단하면 바로 END)
  대화 기억 : MemorySaver (이전 질문·답변을 기억하고 이어감)
============================================================

❓ [1번째] 질문을 입력하세요 (예: 1234 곱하기 5678은? 42를 더하면? / 빈 줄=종료)
> 1234 곱하기 5678은?

▶ 실행 시작 ------------------------------------------------
[think 노드] 🤔 판단 중... (누적 메시지 1개, LLM 호출 시작)
[think 노드] → 결론: 도구 필요함 → calculator({'expression': '1234 * 5678'})  (1.12초)
  └─ 스텝 1 종료: [think] 노드 완료  (누적 1.13초)
[action 노드] ⚙️  실행 시작: calculator({'expression': '1234 * 5678'})
[action 노드] ✅ 실행 완료 → 결과: 7006652  (0.00초)
  └─ 스텝 2 종료: [action] 노드 완료  (누적 1.13초)
[think 노드] 🤔 판단 중... (누적 메시지 3개, LLM 호출 시작)
[think 노드] → 결론: 도구 불필요, 직접 답변 생성 완료 ("1234 곱하기 5678은 7,006,652입니다....")  (2.20초)
  └─ 스텝 3 종료: [think] 노드 완료  (누적 3.33초)

[think 노드] ✅ 최종 답 (3.33초 소요):
1234 곱하기 5678은 7,006,652입니다.
------------------------------------------------------------
■ 1번째 턴 종료 (총 3스텝, 3.33초)
```

답이 끝나도 프로그램은 종료되지 않고, 곧바로 `❓ [2번째] 질문을 입력하세요...`가 다시 뜹니다.

`think`(판단: 도구가 필요하다) → `action`(행동: 계산기 실행) → `think`(다시 판단: 이제 답할 수 있다, 끝) 순서로
**판단↔행동이 한 바퀴 왕복**한 게 보이시나요? 챗봇이면 그냥 한 번에 답(틀릴 수도 있는)을 뱉고 끝입니다.

> 💡 질문이 더 복잡해서(`"1234 곱하기 5678은? 그 결과에 42도 더해줘"` 등) AI가 계산을 여러 단계로
> 나눠서 판단하면, `think ⇄ action`이 **여러 번** 왕복하는 것도 볼 수 있습니다. 매번 몇 번 왕복하는지,
> 왕복마다 몇 초 걸리는지까지 위 로그에 그대로 찍힙니다.

### 대화 루프 — 질문 한 번 하고 끝나지 않는다 🔁

`think ⇄ action`이 "**한 질문 안에서**" 왕복하는 반복이라면, 프로그램 전체를 감싸는
`while True` 루프는 "**질문 자체**"를 반복합니다. 답을 한 번 받고 나면 프로그램이 끝나는 게 아니라
계속 다음 질문을 받고, **빈 줄만 입력해야** 대화가 끝납니다. (이게 없으면, 예를 들어 AI가 바로 답하지
않고 "어떤 스타일을 원하세요?"처럼 **되물었을 때** 이어서 답할 방법이 없어져 버립니다.)

위 예시에 이어서 `1000 곱하기 2000은?`이라고 2번째 질문을 넣어보면, 이번에도 `think ⇄ action`이
왕복하면서 **다시 계산기(action)가 실행되는 것**과, 2번째 턴이 1번째 턴을 **기억하고 있는 것**을
동시에 볼 수 있습니다:

```
❓ [2번째] 질문을 입력하세요 (예: 1234 곱하기 5678은? 42를 더하면? / 빈 줄=종료)
> 1000 곱하기 2000은?

▶ 실행 시작 ------------------------------------------------
[think 노드] 🤔 판단 중... (누적 메시지 5개, LLM 호출 시작)
[think 노드] → 결론: 도구 필요함 → calculator({'expression': '1000 * 2000'})  (0.71초)
  └─ 스텝 1 종료: [think] 노드 완료  (누적 0.71초)
[action 노드] ⚙️  실행 시작: calculator({'expression': '1000 * 2000'})
[action 노드] ✅ 실행 완료 → 결과: 2000000  (0.00초)
  └─ 스텝 2 종료: [action] 노드 완료  (누적 0.72초)
[think 노드] 🤔 판단 중... (누적 메시지 7개, LLM 호출 시작)
[think 노드] → 결론: 도구 불필요, 직접 답변 생성 완료 ("1000 곱하기 2000은 2,000,000입니다....")  (0.79초)
  └─ 스텝 3 종료: [think] 노드 완료  (누적 1.51초)

[think 노드] ✅ 최종 답 (1.51초 소요):
1000 곱하기 2000은 2,000,000입니다.
------------------------------------------------------------
■ 2번째 턴 종료 (총 3스텝, 1.51초)

❓ [3번째] 질문을 입력하세요 (예: 1234 곱하기 5678은? 42를 더하면? / 빈 줄=종료)
>
👋 대화를 종료합니다.
```

2번째 턴이 시작할 때 `누적 메시지 5개`(질문1 + AI 답변 + 도구결과 + AI 답변 + 질문2)로 시작하는 게 보이시나요?
1번째 턴에서 쌓인 메시지 4개를 **기억한 채로** 새 질문 1개가 더해진 겁니다. 코드로는 두 가지를 더했습니다.

```python
# ① MemorySaver: thread_id별로 지금까지 오간 메시지를 기억해두는 저장소
app = graph.compile(checkpointer=MemorySaver())

# ② 대화 루프: 빈 줄을 입력할 때까지 계속 다음 질문을 받는다
config = {"configurable": {"thread_id": "cli-session"}}
while True:
    question = input("❓ ...\n> ")
    if not question.strip():
        break
    # 이번 턴에 "새로 한 말"만 넘겨도, MemorySaver가 이전 대화를 자동으로 이어 붙여준다
    for step in app.stream({"messages": [HumanMessage(content=question)]}, config):
        ...
```

### `basic_graph.py`와 뭐가 달라졌나

| 요소 | basic_graph.py (챗봇) | tool_agent.py (에이전트) |
|---|---|---|
| 노드 | 1개 (`answer`) | 2개 (`think` / `action`) |
| 엣지 | 일직선 (시작→노드→끝) | **갈림길**(조건 분기) + **반복**(행동→판단) |
| 도구 | 없음 | 계산기 (`@tool`) |

딱 이 두 가지 — **갈림길**과 **반복** — 가 챗봇을 에이전트로 바꿉니다.

> 🔎 **직접 실험**: 계산이 필요 없는 질문(`"안녕?"`)을 넣어보세요. `think`가 도구 없이
> 바로 끝으로 가는 것(= 조건 분기의 **다른 쪽 길**)을 눈으로 확인할 수 있습니다.

## 5. 바이브코딩 미션 🚀

이제 구조를 이해했으니, AI에게 요청해서 **직접 에이전트를 만들어보세요.**

> "tool_agent.py를 참고해서, ○○하는 랭그래프 에이전트를 만들어줘.
> 모델은 gemini-2.5-flash-lite, API 키는 .env의 GOOGLE_API_KEY를 써."

추천 미션 (쉬운 순):
1. **번역 에이전트** — 한국어 입력 → 영어로 번역해서 출력 (노드 1개 응용)
2. **3단계 요약 에이전트** — 긴 글 → `요약 노드` → `핵심단어 추출 노드` 2개를 이어 출력 (노드 연결)
3. **판단 에이전트** — 입력이 질문이면 답하고, 아니면 맞장구치기 (`add_conditional_edges` = 갈림길)
4. **나만의 도구 에이전트** — `calculator` 자리에 새 도구(예: 글자 수 세기, 랜덤 뽑기)를 만들어 끼우기

**미션의 진짜 목표**: 결과 코드에서 **노드가 몇 개인지, 화살표(갈림길·반복 포함)가 어떻게 이어졌는지** 스스로 찾아 설명하기.
