# 5단계 — 내 도메인 에이전트 실습

4단계까지는 **남이 만든 구조를 읽었습니다.** 5단계부터는 **내 것으로 만듭니다.**

원우마다 도메인이 다르니 결과물도 전부 달라집니다. 그게 목적입니다.

## 난이도

| 표시 | 대상 | 할 일 |
|---|---|---|
| 🟢 | 전원 | 실행하고 관찰하기. 코딩 없음 |
| 🟡 | 전원 (권장) | 프롬프트·분류 항목을 내 도메인으로 바꾸기 |
| 🔴 | 개발 트랙 | 노드 추가, 도구 연결 |

---

## 1. 먼저 실행만 🟢

[`domain_agent.py`](domain_agent.py)는 미리 만들어둔 **업무 도우미 에이전트**입니다.
2-2단계의 [`agent.py`](../02-web/02-web-goal/agent.py)와 같은 랭그래프인데, 노드가 몇 개 더 많을 뿐입니다.

```powershell
# .env 설정과 pip install은 2-2단계에서 이미 완료
python 05-handson/domain_agent.py
```

### 무엇을 하나요?

요청을 받으면 에이전트가 **스스로 무슨 종류의 일인지 판단**해서 알맞은 담당 노드로 보냅니다.

```
                          ┌─> [📝 요약 노드]
[요청 입력] ─> [분류 노드] ┼─> [✏️ 초안 노드]
                          ├─> [🔍 검토 노드]
                          └─> [💬 대화 노드]
```

이 **"스스로 판단해서 갈림길을 고르는 것"(조건 분기)** 이 챗봇과 에이전트의 차이입니다.

> ★ 분류 기준이 **도메인이 아니라 "일의 종류"** 인 것에 주목하세요.
> 요약·초안·검토는 영업이든 행정이든 연구든 제조든 인사든 전부 필요합니다.
> 그래서 이 에이전트 하나가 원우 전원에게 그대로 돌아갑니다.

### 이렇게 입력해보세요

각자 자기 도메인의 실제 상황으로 바꿔서 넣어보면 더 좋습니다.

| 넣어볼 것 | 어느 노드로 갈까요? |
|---|---|
| `이번 분기 매출 12% 증가, 신규 고객 34곳, 이탈 5곳. 정리해줘.` | 📝 요약 |
| `다음 주 월요일 팀 회의 공지 메일 써줘. 장소는 3층 회의실.` | ✏️ 초안 |
| `'우리 제품이 업계 1위입니다'라는 홍보 문구, 이대로 나가도 될까?` | 🔍 검토 |
| `랭그래프에서 조건부 엣지가 뭐야?` | 💬 대화 |

답변 위에 **어느 노드가 처리했는지** 표시됩니다.
터미널에는 `[분류] → summarize` 처럼 판단 결과도 찍힙니다.

**같은 프로그램인데 요청에 따라 다른 길로 가는 것** — 이걸 눈으로 확인하는 게 1번의 전부입니다.

## 2. 일부러 깨뜨려보기 🟢

잘 도는 걸 보는 것보다 **어디서 무너지는지** 보는 게 훨씬 많이 남습니다.

### 실험 ① 분류를 헷갈리게 해보기

```
이 보고서 요약해서 그걸로 메일 초안까지 써줘
```

요약인가요 초안인가요? **한 번에 하나의 노드만 고를 수 있습니다.**
이게 지금 구조의 한계입니다. → 해결하려면 노드를 **이어 붙여야** 합니다 (4번).

### 실험 ② 모르는 걸 물어보기

```
랭그래프에서 조건부 엣지가 뭐야?
```

그럴듯한 답이 나오지만 **틀렸을 가능성이 높습니다.**
Gemini는 "조건부 엣지"를 그래프 이론 용어로 해석해서 엉뚱한 설명을 내놓곤 합니다.

> 🎯 **이게 핵심 장면입니다.**
> 이 에이전트에는 **도구가 없습니다.** 아는 것만 말하고, 모르면 지어냅니다.
> 우리 회사 재고도, 우리 팀 규정도, 내 연구실 논문 목록도 모릅니다.
>
> [2-2단계 `agent.py`](../02-web/02-web-goal/agent.py)에는 `lookup` 도구가 있었죠?
> **그 차이가 실무에서 쓸 수 있느냐 없느냐를 가릅니다.**

### 실험 ③ 분류 프롬프트 망가뜨리기

[`domain_agent.py`](domain_agent.py)의 `classify_node` 프롬프트에서 항목 설명을 한 줄 지우고 실행해보세요.
**분류가 눈에 띄게 나빠집니다.** 프롬프트 한 줄의 무게를 체감하는 실험입니다.

## 3. 내 도메인으로 바꾸기 🟡

**여기서부터가 진짜 과제이고, 한 학기 내내 이어집니다.**

### 3-1. 먼저 표부터 채우기 (코딩 아님)

코딩보다 이게 더 중요합니다. 2-2단계에서 채웠던 표를 다시 꺼내세요.

| 칸 | 내 도메인 |
|---|---|
| 내가 반복해서 하는 일 3가지 | |
| 그중 AI에게 맡길 만한 것 | |
| 그 일을 하려면 **어떤 자료를 찾아와야** 하나 | |
| 결과물의 모양 (메일? 표? 문단?) | |

> 세 번째 칸이 안 채워지면 그게 진짜 과제입니다.
> "우리 조직 데이터를 어디서 가져올 것인가"가 도메인 적용의 실제 난관입니다.

### 3-2. 바꿀 곳은 두 군데뿐

**① 분류 항목** — `classify_node`의 프롬프트

```python
- 긴 글·자료를 짧게 정리해달라는 요청이면: summarize
- 새로 글·문서·메시지를 써달라는 요청이면: draft
- 이미 있는 것을 검토·분석·평가해달라는 요청이면: review
```

이 목록을 3-1에서 적은 **내 업무 3가지**로 바꿉니다.

**② 각 노드의 프롬프트** — `summarize_node` / `draft_node` / `review_node`

각 노드 안의 프롬프트를 내 도메인 말투와 형식으로 바꿉니다.
(`graph.add_conditional_edges`의 딕셔너리 키도 같이 맞춰야 합니다)

### 바이브코딩 미션

> "`domain_agent.py`를 참고해서, ○○하는 노드를 추가해줘.
> 모델은 gemini-2.5-flash-lite, API 키는 `.env`의 `GOOGLE_API_KEY`를 써."

쉬운 순:
1. 분류 항목과 노드 프롬프트를 내 도메인으로 바꾸기
2. 노드를 하나 더 추가하기
3. 분류 결과를 답변에 같이 보여주기 (왜 이 노드로 갔는지)
4. 답변을 파일로 저장하기

**미션의 진짜 목표:** 결과 코드에서 **노드가 몇 개이고 화살표가 어떻게 이어졌는지** 스스로 짚어 설명하기.

## 4. 더 나아가기 🔴

### 4-1. 노드 이어 붙이기 (실험 ①의 해결)

지금은 분류 → 노드 하나 → 끝입니다. `요약 → 초안`처럼 **이어지게** 하려면
`add_edge("summarize", "draft")` 로 END 대신 다음 노드를 가리키면 됩니다.

### 4-2. 도구 붙이기 (실험 ②의 해결)

[2-2단계 `agent.py`](../02-web/02-web-goal/agent.py)의 `@tool` + `think ↔ act` 구조를
이 그래프의 노드 하나에 얹으면, 그 노드만 **자료를 찾아오는 노드**가 됩니다.
구조는 [4-1단계 6절](../04-agent/01-agent-basic.md#6-1단계--같은-걸-stategraph로-다시-쓰기)에 있습니다.

### 4-3. 사람 승인 붙이기

메일 발송처럼 되돌릴 수 없는 일이라면 `interrupt_before`로 사람이 확인한 뒤 진행하게 합니다.
→ [4-1단계 7-2](../04-agent/01-agent-basic.md#7-2-interrupt--사람-승인-hitl)

### 4-4. 노드가 커지기 시작하면 — 사례 연구 🟢

한 학기 동안 키우다 보면 **노드 하나가 자꾸 커지는** 벽을 만납니다.
프롬프트가 200줄이 되고, 고치면 다른 게 깨집니다.

[`writing-skills.md`](writing-skills.md)는 그 벽을 실제로 맞고 넘은 기록입니다 —
글쓰기 에이전트를 **스킬 하나에서 7개로 쪼갠** 과정과, 쪼개는 기준 3가지,
그리고 **실패가 규칙이 된 표**를 정리했습니다.

> 코딩 없이 읽기만 해도 됩니다. **비개발자에게 특히 권합니다** —
> "일을 어떤 단위로 자를 것인가"는 코드 문제가 아니라 업무 설계 문제입니다.

## 📌 한 학기 진행

5단계는 **한 번 하고 끝나는 실습이 아닙니다.** 각자 자기 리포에서 학기 내내 키워갑니다.

| 시기 | 목표 |
|---|---|
| 초반 | 분류 항목·프롬프트를 내 도메인으로 교체 |
| 중반 | 도구 하나 붙이기 (내 조직 데이터 조회) |
| 후반 | 사람 승인 게이트 + 결과 저장 |
| 마무리 | 무엇이 되고 무엇이 안 됐는지 정리 → 발표 |
